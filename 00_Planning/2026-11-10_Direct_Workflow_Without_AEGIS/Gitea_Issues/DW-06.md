# [Direct] Show direct jobs clearly in Jobs

Labels: P2.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: [DW-04 #64](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/64).

## Goal

In **Jobs**, a user sees at a glance whether a job runs the AEGIS or the direct
workflow. A direct job shows only the steps it has, the attempt number and the
verification result.

## Decisions

- **Workflow label.** The job list and the job page show the workflow: "AEGIS" or
  "Direct".
- **Steps.** A direct job shows only *Implementation* and *Validation* (stages
  `build` and `validate`), then done. It shows no Framing, Specification or Design
  and no AEGIS task.
- **The job page shows:**
  - the attempt number;
  - the verification result: command, then passed, failed, timed out, or "not
    configured: unverified";
  - the duration and the output tail.
- **AEGIS jobs** look exactly as today.
- **Help.** It explains that direct jobs use the Implementation and Validation
  stage limits.

## Done when

- [ ] A direct job shows the *Direct* label, only Implementation and Validation,
      the attempt number and each verification outcome (passed, failed, timed out,
      not configured). This is covered by unit tests on the job model and by the
      jobs e2e spec.
- [ ] An AEGIS job renders as before (existing tests unchanged).
- [ ] A job record with an unknown workflow value is shown as an error state, not
      guessed (negative test).
- [ ] Help is updated in four locales; `CHANGELOG.md` and a four-locale release
      note. The journal records `release-notes: added` and `help: updated`.

## Working rules

- **Workflow and authority.** ADORE runs this ticket as one AEGIS task in this
  repository. Follow `AGENTS.md`, which is authoritative, and `.agentic/AGENTS.md`.
  The plan is `00_Planning/2026-11-10_Direct_Workflow_Without_AEGIS/PLAN.md`; read
  its sections 1 and 4.
- **Conflicts.** If this ticket conflicts with the plan, or the code has moved so a
  decision no longer fits, ask in the questions file instead of deciding.
- **AEGIS files.** `04_Software/adore/aegis.py` is ADORE's own AEGIS client and may
  be edited when needed. Never edit the AEGIS payload under `.agentic/`
  (`aegis.py`, `steps/`, `templates/`, `aegis.toml`).
- **Stored data.** No migrations or compatibility with earlier builds.
- **Documentation in the same change.**
  - A user-visible change needs `CHANGELOG.md` and a four-locale entry in
    `04_Software/adore/release_notes.toml`.
  - An interface or workflow change needs help in all four locales.
  - Component pages in `05_SoftwareDocu/` are updated too.
- **Tests.** Every public behaviour gets one happy test and negative tests at its
  trust boundaries. Tests run offline, using the existing fakes.
- **Test runs.** Run targeted tests while building; the full suite runs once, in
  validate, through the AEGIS strict check.
- **Style.** LF line endings, license headers, `01_Documentation/Code_Style.md`.
- **Git.** ADORE commits, pushes and opens the PR; never do these yourself.

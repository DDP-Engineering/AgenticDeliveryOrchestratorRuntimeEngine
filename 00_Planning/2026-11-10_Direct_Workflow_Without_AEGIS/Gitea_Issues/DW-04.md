# [Direct] Enroll repositories without AEGIS in the web interface

Labels: P1.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: [DW-03 #63](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/63).

## Goal

An administrator enrolls a repository without AEGIS from **Projects → Enroll new
project** and sees which workflow it will use. The *Verification command* can be
set at enrollment and later in **Settings → Implementation**.

## Decisions

- **Enrollment no longer refuses a repository without AEGIS.**
  - `.agentic/aegis.py` present means the AEGIS workflow.
  - `.agentic/aegis.toml` is no longer required, matching the run probe.
  - The live probe still runs at pre-pick.
- **The readiness row.** The "AEGIS files" check becomes an information row,
  *Workflow*, that never blocks. It shows "AEGIS, stage by stage" or "Direct, no
  AEGIS found". It names no version, because the web check runs nothing.
- **The *Verification command* field.**
  - Enrollment: optional and empty in this ticket (DW-05 pre-fills it).
  - For AEGIS repositories the field is replaced by the note "Uses the
    repository's AEGIS test commands".
  - **Settings → Implementation**: the same field, saved through the existing
    reviewed save flow as `[workflow] verify_command`.
- **The error is removed.** The `repository_aegis_missing` error and its copy
  disappear.
- **Help shows only what exists.** It describes both workflows and the field.

## Done when

- [ ] A repository without AEGIS enrolls, readiness shows *Direct*, the project is
      created, and no file is written into the clone.
- [ ] A repository with `.agentic/aegis.py` but without `aegis.toml` enrolls with
      the AEGIS workflow.
- [ ] The verification command saves from enrollment and from Settings →
      Implementation. A multi-line value is refused with a message (negative
      tests, API and interface).
- [ ] The enrollment and settings e2e specs cover both workflows and pass.
- [ ] Help is updated in four locales and `node --test tests/help.test.mjs`
      passes.
- [ ] No interface or help text says AEGIS is required. This search returns only
      AEGIS-workflow descriptions:
      `git grep -n -i -E "Install AEGIS|AEGIS installed|aegis_missing" -- 04_Software/web/src 04_Software/adore/web`.
- [ ] `CHANGELOG.md` and a four-locale release note. The journal records
      `release-notes: added` and `help: updated`.

## Stop and ask (questions file) if

- The Implementation settings tab cannot hold a free-text field without a new
  settings mechanism.
- Enrollment would need to run a command in the clone to decide the workflow.

## Working rules

- **Workflow and authority.** ADORE runs this ticket as one AEGIS task in this
  repository. Follow `AGENTS.md`, which is authoritative, and `.agentic/AGENTS.md`.
  The plan is `00_Planning/2026-11-10_Direct_Workflow_Without_AEGIS/PLAN.md`; read
  its sections 1 and 4.
- **Conflicts.** If this ticket conflicts with the plan, or the code has moved so a
  decision no longer fits, ask in the questions file instead of deciding.
- **AEGIS files.** `04_Software/adore/aegis.py` is ADORE's own AEGIS client and may
  be edited when needed. Never edit the AEGIS payload under `.agentic/`
  (`aegis.py`, `steps/`, `templates/`, `aegis.toml`).
- **Stored data.** No migrations or compatibility with earlier builds.
- **Documentation in the same change.**
  - A user-visible change needs `CHANGELOG.md` and a four-locale entry in
    `04_Software/adore/release_notes.toml`.
  - An interface or workflow change needs help in all four locales.
  - Component pages in `05_SoftwareDocu/` are updated too.
- **Tests.** Every public behaviour gets one happy test and negative tests at its
  trust boundaries. Tests run offline, using the existing fakes.
- **Test runs.** Run targeted tests while building; the full suite runs once, in
  validate, through the AEGIS strict check.
- **Style.** LF line endings, license headers, `01_Documentation/Code_Style.md`.
- **Git.** ADORE commits, pushes and opens the PR; never do these yourself.

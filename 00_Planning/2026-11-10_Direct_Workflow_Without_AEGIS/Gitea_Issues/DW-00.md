# [Direct] Read the agent prompts from files shipped with ADORE

Labels: P1, change.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: [DW-01 #61](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/61). DW-02 builds on it: its new direct prompt
goes straight into a file here.

## Goal

Every text ADORE sends to the Pi agent lives in files in a `prompts/` folder that
ships with the application, instead of in Python string literals. The goal is that
prompts can be read, reviewed and changed as files. Behaviour does not change: for
the same run, Pi receives exactly the same text as before.

## Context

ADORE itself is deterministic; its only agent-facing texts are these string
literals (line numbers at `b2e6442`):

- **Stage prompt.** `_stage_prompt` (`adore/orchestrator.py:1508-1600`) composes
  about ten fixed paragraphs plus conditional parts:
  - the frame and quick-label paragraphs;
  - the recovery context and the human thread;
  - two variants of the system-package permission;
  - the network paragraph;
  - the closing rules.
- **Recovery texts** passed as `failure_context`: `orchestrator.py:1193-1199`,
  `:1241`, `:1296-1303`, `:1312` and `:1867-1871`.
- **Review texts:** `_pipeline_brief` (`orchestrator.py:2930-2946`) and
  `_TICKET_CONTENT_CHANGED_NOTE` (`:120`).
- **System-prompt notices:** `INTERNET_OFF_NOTICE` (`adore/executor/launcher.py:67-73`)
  and the server notice (`launcher.py:596`).

## Decisions

- **Location.** Folder `04_Software/adore/prompts/`, one Markdown file per
  fragment, grouped by use: `stage/`, `recovery/`, `review/`, `system/`. It is
  read with `Path(__file__)` like `pi_catalog.json` and ships in the wheel and the
  portable package. There is no setting that points elsewhere.
- **License header.** Each file starts with the project license header as a
  Markdown comment (`<!-- ... -->`). The loader removes that leading comment, so
  the header never reaches the agent.
- **Placeholders.**
  - Values are named `$placeholders`, substituted with `string.Template`; `$$` is
    a literal `$`. Braces in ticket text or code examples need no escaping.
  - Values such as the ticket title, ticket body, sanitised evidence and human
    thread are inserted as data and never re-parsed as templates.
- **A small loader module**, `adore/prompts.py`.
  - It loads and checks every file once, at orchestrator construction.
  - It renders a fragment with the values the caller passes.
  - It fails closed with a typed `PromptError` naming the file: missing,
    unreadable, not UTF-8, invalid `$` syntax, or a placeholder not supplied at
    render time.
- **Composition logic stays in code.** Which fragments are used, in which order,
  under which conditions, and how they are joined is unchanged in
  `_stage_prompt` and its callers. Only the texts move.
- **Stays in code:**
  - the model-connection challenge (`adore/web/model_connection.py:144`), whose
    reply is checked exactly;
  - the `author: body` thread rendering;
  - `_sanitize`;
  - every non-prompt string (status comments, logs, errors).
- **Identical output.**
  - Before moving anything, capture what the current code renders for
    representative cases: each stage, frame with and without the quick label,
    recovery context, human thread, packages on and off, every network mode, and
    each recovery and review text.
  - Keep those captures as expected test data; after the move, the rendered text
    must be byte-identical.
- **Out of scope:** prompt evaluation, archiving the prompt sent, prompt preview
  commands, changing the wording of any prompt, and prompts owned by others (Pi's
  own system prompt, the target repository's `AGENTS.md`, the AEGIS step files).

## Scope

In:

- new `adore/prompts/` and `adore/prompts.py`;
- `adore/orchestrator.py` and `adore/executor/launcher.py`;
- new `tests/test_prompts.py` (loader contract and identical-output tests);
- updated assertions in `tests/test_orchestrator.py`;
- packaging checks (wheel and portable package include the folder);
- new `05_SoftwareDocu/Component_Prompts.md` from the template, plus the component
  index;
- `Component_Orchestrator.md` and `Component_Executor_Launcher.md`;
- `CHANGELOG.md` (Changed: agent prompts are files in `adore/prompts/`).

## Done when

- [ ] No agent-facing prompt text from the Context list remains as a string literal
      in `adore/orchestrator.py` or `adore/executor/launcher.py`. Each one is a file
      under `adore/prompts/`.
- [ ] For every captured case, the rendered prompt and notices are byte-identical
      to the captures taken before the move (`tests/test_prompts.py`).
- [ ] Loader happy test: all shipped files load, and every placeholder each
      fragment uses is supplied by its caller.
- [ ] Loader negative tests, each a `PromptError` naming the file:
  - [ ] a missing file;
  - [ ] invalid UTF-8;
  - [ ] invalid `$` syntax;
  - [ ] a placeholder not supplied;
  - [ ] a ticket body containing `$name` and `{x}` is inserted literally, not
        substituted.
- [ ] The license header comment never appears in a rendered prompt (test).
- [ ] The built wheel contains every file under `adore/prompts/`, and so does the
      portable package if it does not ship the wheel unchanged.
- [ ] Component documentation and the `CHANGELOG.md` entry are written. The journal
      records `release-notes: none (internal change, no user-visible behaviour)`
      and `help: none (no interface change)`.

## Stop and ask (questions file) if

- A prompt text cannot move without changing what Pi receives, for example
  because of whitespace or joining rules that a file cannot express.
- Moving a text would require changing the composition logic.
- The portable package needs a manifest change outside `02_Tools/` packaging code.

## Working rules

- **Workflow and authority.** ADORE runs this ticket as one AEGIS task in this
  repository. Follow `AGENTS.md`, which is authoritative, and `.agentic/AGENTS.md`.
  The plan is `00_Planning/2026-11-10_Direct_Workflow_Without_AEGIS/PLAN.md`; read
  its sections 1 and 4.
- **Conflicts.** If this ticket conflicts with the plan, or the code has moved so a
  decision no longer fits, ask in the questions file instead of deciding.
- **AEGIS files.** `04_Software/adore/aegis.py` is ADORE's own AEGIS client and may
  be edited when needed. Never edit the AEGIS payload under `.agentic/`
  (`aegis.py`, `steps/`, `templates/`, `aegis.toml`).
- **Stored data.** No migrations or compatibility with earlier builds.
- **Documentation in the same change.**
  - A user-visible change needs `CHANGELOG.md` and a four-locale entry in
    `04_Software/adore/release_notes.toml`.
  - An interface or workflow change needs help in all four locales.
  - Component pages in `05_SoftwareDocu/` are updated too.
- **Tests.** Every public behaviour gets one happy test and negative tests at its
  trust boundaries. Tests run offline, using the existing fakes.
- **Test runs.** Run targeted tests while building; the full suite runs once, in
  validate, through the AEGIS strict check.
- **Style.** LF line endings, license headers, `01_Documentation/Code_Style.md`.
- **Git.** ADORE commits, pushes and opens the PR; never do these yourself.

# [Direct] Suggest the verification command from repository files

Labels: P2.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: [DW-04 #64](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/64).

## Goal

When a repository has no AEGIS, enrollment and `adore init` pre-fill the
*Verification command* with a suggestion read from the repository's files, and say
where it came from. A human keeps, edits or clears it.

## Decisions

- **A pure function.** It takes the clone's root path and returns
  `(command, source file)` or nothing. It reads file names and manifest contents
  only.
  - It never runs a command and never uses the network.
  - It ignores links that leave the repository and files larger than 1 MiB.
- **Matching rules.**
  - The first match at the repository root wins, in the table order below.
  - When the root has no match and exactly one first-level directory matches, the
    suggestion is prefixed with `cd <dir> && `.
  - Several matching first-level directories give no suggestion.

  | Found | Suggestion |
  |---|---|
  | `package.json` with `scripts.test` that is not npm's "no test specified" placeholder | `npm test`; `pnpm test` with `pnpm-lock.yaml`; `yarn test` with `yarn.lock` |
  | `pyproject.toml`, `pytest.ini` or `tox.ini` | `uv run pytest -q` with `uv.lock`, else `python -m pytest -q` |
  | `go.mod` | `go test ./...` |
  | `Cargo.toml` | `cargo test` |
  | `pom.xml` | `mvn -q test` |
  | `build.gradle` or `build.gradle.kts` | `./gradlew test` with `gradlew`, else `gradle test` |
  | `*.sln` or `*.csproj` | `dotnet test` |
  | `Makefile` with a `test:` target | `make test` |
- **Web.** Enrollment pre-fills the field for direct repositories with the hint
  "Suggested from `<file>`". It is saved only by the human's Create or Save.
  - AEGIS repositories get no suggestion.
  - Settings never overwrites a saved value with a suggestion.
- **CLI.** The `adore init` wizard offers the same suggestion as the default answer
  when the target has no AEGIS.

## Scope

In:

- a new `adore/verification_hint.py`, or the closest existing module if one fits
  better;
- `adore/web/app.py`: the enrollment preview returns the suggestion;
- `adore/wizard.py`;
- the web interface: `EnrollmentWizard.tsx` and its copy in four locales;
- tests;
- help in four locales: `projects.md`;
- documentation: `01_Documentation/Web_Interface.md`, `Configuration_Reference.md`
  and the component pages;
- `CHANGELOG.md` and a release note.

Out: running or validating the suggested command.

## Done when

- [ ] One table-driven test per table row, including the `cd <dir> && ` case.
- [ ] Negative tests:
  - [ ] a malformed `package.json` gives no suggestion and no error;
  - [ ] the placeholder test script gives no suggestion;
  - [ ] a symlinked manifest that points outside the repository is ignored;
  - [ ] two matching first-level directories give no suggestion;
  - [ ] a manifest over 1 MiB is not read.
- [ ] The enrollment preview shows the suggestion and its source for a repository
      without AEGIS, and nothing for an AEGIS repository (API test and e2e).
- [ ] The `adore init` wizard offers the suggestion as its default answer
      (wizard test).
- [ ] Help is updated in four locales; `CHANGELOG.md` and a four-locale release
      note. The journal records `release-notes: added` and `help: updated`.

## Working rules

- **Workflow and authority.** ADORE runs this ticket as one AEGIS task in this
  repository. Follow `AGENTS.md`, which is authoritative, and `.agentic/AGENTS.md`.
  The plan is `00_Planning/2026-11-10_Direct_Workflow_Without_AEGIS/PLAN.md`; read
  its sections 1 and 4.
- **Conflicts.** If this ticket conflicts with the plan, or the code has moved so a
  decision no longer fits, ask in the questions file instead of deciding.
- **AEGIS files.** `04_Software/adore/aegis.py` is ADORE's own AEGIS client and may
  be edited when needed. Never edit the AEGIS payload under `.agentic/`
  (`aegis.py`, `steps/`, `templates/`, `aegis.toml`).
- **Stored data.** No migrations or compatibility with earlier builds.
- **Documentation in the same change.**
  - A user-visible change needs `CHANGELOG.md` and a four-locale entry in
    `04_Software/adore/release_notes.toml`.
  - An interface or workflow change needs help in all four locales.
  - Component pages in `05_SoftwareDocu/` are updated too.
- **Tests.** Every public behaviour gets one happy test and negative tests at its
  trust boundaries. Tests run offline, using the existing fakes.
- **Test runs.** Run targeted tests while building; the full suite runs once, in
  validate, through the AEGIS strict check.
- **Style.** LF line endings, license headers, `01_Documentation/Code_Style.md`.
- **Git.** ADORE commits, pushes and opens the PR; never do these yourself.

# [Direct] Direct workflow in the orchestrator, unverified candidates

Labels: P1.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: [DW-01 #61](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/61).

## Goal

ADORE claims a ticket in a repository without `.agentic/aegis.py`. Pi implements it
in a bounded session, and ADORE hands the candidate to the existing human approval,
marked unverified. This ticket covers the configuration and CLI path. The
verification command arrives in DW-03, and web enrollment in DW-04.

## Decisions

- **Run state.** The run state gets `workflow`, either `"aegis"` or `"direct"`,
  recorded at claim and never changed afterwards. A direct run carries no AEGIS task
  id and uses the stages `build`, `validate` and `done`; it starts at `build`.
- **Detection.**
  - `.agentic/aegis.py` absent in the run's worktree means direct.
  - The pre-pick check applies the same test to the clone and probes only when the
    file exists (`orchestrator.py:377-385`, `:945-954`).
  - When the file exists, today's probe and AEGIS path run unchanged, including the
    refusal of unsupported payloads (`workflow_unavailable`).
- **Branch point.** `_conduct` branches after `_provision`
  (`orchestrator.py:1074-1091`) into a new `_conduct_direct`. There is no shared
  workflow interface.
- **Sessions.** One fresh Pi session per attempt, with the same launcher,
  container, egress, budgets and timeouts (`per_gate_timeout_seconds`,
  `stage_timeout_overrides.build`), and the same questions file and clarification
  resume as today.
- **Prompt.** A new `_direct_prompt` carries the ticket title and body. It tells
  Pi to:
  - read the repository's own instructions when present (`AGENTS.md`,
    `CLAUDE.md`, `CONTRIBUTING.md`, `README`);
  - implement completely, with tests where the repository has tests;
  - never commit, push, open or merge an MR/PR, or access forge credentials;
  - ask blocking questions in the questions file;
  - finish by writing a short summary (what changed, how it was checked) to
    `ADORE_SUMMARY.md` at the worktree root.

  It reuses the container permission and network paragraphs of `_stage_prompt`
  (`orchestrator.py:1568-1587`).
- **Done.** A direct run is done when:
  - the session settled without error;
  - there is no questions file;
  - the progress fingerprint changed, not counting `ADORE_SUMMARY.md` and the
    questions file (`isolation.py:823-841`).

  ADORE then:
  1. keeps the summary text and removes the file;
  2. makes the checkpoint commit;
  3. records `validation_evidence` as "not configured" and the
     `candidate_fingerprint`;
  4. sets stage `done` and lifecycle `awaiting-approval`.
- **Failures.**
  - No changes: the run fails with `NO_CHANGES` and carries the summary.
  - A Pi error or timeout uses the existing failure accounting.
- **Ticket and MR/PR texts.** For direct runs, the approval comment
  (`_approval_body`, `orchestrator.py:1933`) and the MR/PR body (`_mr_body`, `:2146`)
  show:
  - the summary;
  - the number of changed files;
  - "Verification: not configured. This candidate is unverified.";
  - no AEGIS task line.
- **Doctor and init messages.**
  - `adore init` and doctor report a missing payload as information: "No AEGIS
    found: tickets run in the direct workflow".
  - The AEGIS remediation text (`doctor.py:180-188`) no longer says the target must
    carry AEGIS.
- **Stored data.** No migration: a persisted run without `workflow` is refused with
  `StateError` naming what to delete, plus one `CHANGELOG.md` line.

## Scope

In:

- `adore/state.py`: the field and its validation;
- `adore/orchestrator.py`: pre-pick, claim, branch point, `_conduct_direct`,
  `_direct_prompt`, approval and MR texts;
- `adore/isolation.py`, if the fingerprint needs the two excluded file names;
- `adore/doctor.py` and `adore/wizard.py`: the messages;
- `adore/cli.py` start reasons (`:633-645`);
- serialisation of `workflow` in `adore/metrics.py` and `adore/web/jobs.py` (no UI
  change);
- tests;
- documentation:
  - `README.md` "How it works" and "Requirements": AEGIS becomes optional;
  - `01_Documentation/Getting_Started.md` prerequisites;
  - `01_Documentation/Integrating_A_Runtime_Project.md`: the contract with and
    without AEGIS;
  - `05_SoftwareDocu/Component_Orchestrator.md`, `Component_State_Store.md` and
    `Component_Doctor.md`;
- `CHANGELOG.md` and a release note (`new`).

Out:

- the verification command (DW-03);
- web enrollment and help (DW-04);
- the suggested command (DW-05);
- the Jobs display (DW-06).

## Done when

- [ ] A ticket in a repository without `.agentic/aegis.py` reaches
      `awaiting-approval` through one Pi session (orchestrator test with the fake
      executor and fake forge).
- [ ] The approval comment and the published MR/PR body contain Pi's summary and
      say the candidate is unverified.
- [ ] A questions file parks the run. `agent-answered` resumes it in a fresh direct
      session that receives the thread.
- [ ] No changes fails the run with `NO_CHANGES`. A session that only wrote
      `ADORE_SUMMARY.md` counts as no changes.
- [ ] A Pi error, a session timeout and an exhausted budget follow the existing
      failure accounting.
- [ ] Neither `ADORE_SUMMARY.md` nor the questions file appears in any checkpoint
      commit or in the published branch.
- [ ] A repository with AEGIS behaves as before: every existing orchestrator test
      passes unchanged, and an unsupported payload is still refused with no claim.
- [ ] A persisted run without `workflow`, with an unknown value, or a direct run
      that carries a task id, is refused with `StateError` (negative tests).
- [ ] README, Getting Started, the runtime-project contract and the component
      pages describe both workflows, and none says AEGIS is required.
- [ ] `CHANGELOG.md` (including the "delete the run state" line) and a four-locale
      release note. The journal records `release-notes: added` and
      `help: none (web enrollment still requires AEGIS until DW-04)`.

## Stop and ask (questions file) if

- The direct path needs a change to the AEGIS path beyond the branch point and
  shared helpers.
- More than one new run-state field or any new setting seems necessary.
- The change no longer fits one reviewable PR. Propose a split, for example run
  state and workflow selection first, then the direct conductor.

## Working rules

- **Workflow and authority.** ADORE runs this ticket as one AEGIS task in this
  repository. Follow `AGENTS.md`, which is authoritative, and `.agentic/AGENTS.md`.
  The plan is `00_Planning/2026-11-10_Direct_Workflow_Without_AEGIS/PLAN.md`; read
  its sections 1 and 4.
- **Conflicts.** If this ticket conflicts with the plan, or the code has moved so a
  decision no longer fits, ask in the questions file instead of deciding.
- **AEGIS files.** `04_Software/adore/aegis.py` is ADORE's own AEGIS client and may
  be edited when needed. Never edit the AEGIS payload under `.agentic/`
  (`aegis.py`, `steps/`, `templates/`, `aegis.toml`).
- **Stored data.** No migrations or compatibility with earlier builds.
- **Documentation in the same change.**
  - A user-visible change needs `CHANGELOG.md` and a four-locale entry in
    `04_Software/adore/release_notes.toml`.
  - An interface or workflow change needs help in all four locales.
  - Component pages in `05_SoftwareDocu/` are updated too.
- **Tests.** Every public behaviour gets one happy test and negative tests at its
  trust boundaries. Tests run offline, using the existing fakes.
- **Test runs.** Run targeted tests while building; the full suite runs once, in
  validate, through the AEGIS strict check.
- **Style.** LF line endings, license headers, `01_Documentation/Code_Style.md`.
- **Git.** ADORE commits, pushes and opens the PR; never do these yourself.

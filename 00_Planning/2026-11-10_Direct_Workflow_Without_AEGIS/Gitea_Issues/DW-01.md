# [Direct] adore init probes AEGIS with the configured Python

Labels: P1, fix.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: nothing. This is the first ticket ADORE implements on
its own repository. It is small on purpose: it proves the ADORE-on-ADORE setup
(plan section 6) before the larger tickets.

## Goal

`adore init` checks a target repository's AEGIS with the same Python interpreter
that runs use, `[workflow] aegis_python`, instead of a hard-coded `python`.

## Context

- `04_Software/adore/doctor.py:529` and `:544` run `["python", AEGIS_WRAPPER, ...]`.
- Runs use `config.workflow.aegis_python` (`orchestrator.py:1087-1091`).
- So on a host whose interpreter is `python3`, `adore init` reports that python is
  not available, although runs would work.
- `detect_aegis` is called from `adore/wizard.py:790`.

## Decisions

- `detect_aegis` receives the interpreter. Callers pass
  `config.workflow.aegis_python`, which defaults to `"python"`.
- The exit-127 message names the configured interpreter.
- Nothing else in the check changes: it stays informational and never blocks.

## Scope

In:

- `adore/doctor.py` and its caller in `adore/wizard.py`;
- tests in `tests/test_doctor.py` and `tests/test_wizard.py`;
- `05_SoftwareDocu/Component_Doctor.md` and, if it describes the call,
  `Component_Wizard.md`;
- `CHANGELOG.md` (Fixed) and a release note.

Out: anything about repositories without AEGIS (DW-02).

## Done when

- [ ] `detect_aegis` runs the configured interpreter for `--version` and for
      `status --all --json`.
- [ ] Happy test: with a configured `python3`, `python3` is argv[0] of both probe
      commands (fake command runner).
- [ ] Negative tests: exit 127 names the configured interpreter. An unsupported
      version and malformed status JSON are still reported as before.
- [ ] `CHANGELOG.md` has a Fixed entry and `release_notes.toml` a four-locale
      `fixed` note. The journal records `release-notes: added` and
      `help: none (no interface change)`.
- [ ] Component documentation is updated.

## Validation

## Working rules

- **Workflow and authority.** ADORE runs this ticket as one AEGIS task in this
  repository. Follow `AGENTS.md`, which is authoritative, and `.agentic/AGENTS.md`.
  The plan is `00_Planning/2026-11-10_Direct_Workflow_Without_AEGIS/PLAN.md`; read
  its sections 1 and 4.
- **Conflicts.** If this ticket conflicts with the plan, or the code has moved so a
  decision no longer fits, ask in the questions file instead of deciding.
- **AEGIS files.** `04_Software/adore/aegis.py` is ADORE's own AEGIS client and may
  be edited when needed. Never edit the AEGIS payload under `.agentic/`
  (`aegis.py`, `steps/`, `templates/`, `aegis.toml`).
- **Stored data.** No migrations or compatibility with earlier builds.
- **Documentation in the same change.**
  - A user-visible change needs `CHANGELOG.md` and a four-locale entry in
    `04_Software/adore/release_notes.toml`.
  - An interface or workflow change needs help in all four locales.
  - Component pages in `05_SoftwareDocu/` are updated too.
- **Tests.** Every public behaviour gets one happy test and negative tests at its
  trust boundaries. Tests run offline, using the existing fakes.
- **Test runs.** Run targeted tests while building; the full suite runs once, in
  validate, through the AEGIS strict check.
- **Style.** LF line endings, license headers, `01_Documentation/Code_Style.md`.
- **Git.** ADORE commits, pushes and opens the PR; never do these yourself.

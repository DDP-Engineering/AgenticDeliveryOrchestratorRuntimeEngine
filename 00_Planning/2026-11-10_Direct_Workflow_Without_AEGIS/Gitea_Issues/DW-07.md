# [Direct] Live acceptance and documentation audit

Labels: P1, no-agent.

Part of [epic #60](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/60). Depends on: [DW-01 #61](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/61) to [DW-06 #66](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/66). Run by the owner with real
credentials, a real forge and a real container; ADORE never picks it (`no-agent`).

## Goal

Prove the direct workflow end to end on real repositories, prove that the AEGIS
workflow did not change, and remove the last texts that say ADORE works only with
AEGIS repositories.

## Setup

- ADORE built from the integration branch with DW-01 to DW-06 merged, in the usual
  deployment.
- A small sample repository on Gitea without AEGIS, with a few tests (for example a
  Node or Python project).
- A repository with AEGIS: this repository, or the AEGIS test project used for the
  Pi acceptance.

## Done when

- [ ] **AEGIS regression.** One ticket in the AEGIS repository reaches a draft PR
      exactly as before (stages, strict check, approval, PR body).
- [ ] **Direct, verified.**
  - [ ] Enrolling the sample repository shows *Direct* and a suggested command
        with its source.
  - [ ] A ticket reaches a draft PR, and the approval comment shows a passed
        verification.
  - [ ] The repository receives no `.agentic/`, no AGENTS.md, CLAUDE.md or
        .gitignore block, no `ADORE_SUMMARY.md` and no questions file.
- [ ] **Direct, fix attempt.** A ticket whose first attempt breaks a test shows a
      failed verification, a second attempt and a final pass in Jobs and in the
      approval comment.
- [ ] **Direct, unverified.** With the command cleared, the approval comment and
      the PR body say the candidate is unverified.
- [ ] **Clarification.** An ambiguous ticket parks; an answer plus
      `agent-answered` resumes it.
- [ ] **Locations.** Container runs pass; local server runs pass too if the
      ADORE-managed server installation exists.
- [ ] **Documentation audit.**
  - [ ] This search finds only descriptions of the AEGIS workflow itself:
        `git grep -n -i -E "already contain AEGIS|repository-installed AEGIS|Install AEGIS in|must carry an AEGIS|AEGIS installed"`.
  - [ ] README, Getting Started, Web Interface, the runtime-project contract and
        help in four locales agree with one another.
  - [ ] `AGENTS.md` Status, `.agentic/context/project.md` and
        `00_Planning/ADORE_System_Overview.md` describe the direct workflow as
        shipped, not as planned.
- [ ] The epic's Progress list is complete and the epic is closed.

## Validation

Post the evidence on this ticket:

- run ids;
- PR links;
- the approval comment text for each scenario;
- the `git grep` output.

## Stop if

- The AEGIS regression scenario differs from the previous behaviour in anything
  but the new *Workflow* label. Open a fix ticket before closing the epic.

# [Web UX] Add stable display identity and safe paused-enrollment backend contracts

## Tracking
Work item: W02. Priority: P1. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [BASE #4](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/4).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
The current project name is an immutable restricted profile ID, not a human display name. Exact TOML imports pause pickup, but the web new-project flow must guarantee the same safe state before exposing the profile to workers.

## Scope and contract decisions
Add a human display_name separate from the stable existing profile ID. Existing profiles use the ID as their display fallback. Never rename profile directories, state roots, memberships, operation ownership or URLs when display_name changes. Provide server-side deterministic ID validation/availability; an automatically suggested slug still requires collision checking.
Guarantee all web-created projects start with pickup stopped atomically with respect to worker discovery. Existing running projects and unrelated CLI enrollment behaviour remain unchanged unless separately specified.
Return structured setup validation with stable code, field/path and human-readable remediation. Separate structural validity, pickup state and last explicit environment verification. Reuse explicit readiness commands and protect their results against stale configuration revisions. No automatic network/container probes while typing.

## Acceptance criteria
- [ ] New valid web enrollment returns a stable ID, display name and pickup-stopped state; the worker cannot observe an intermediate pickup-active project.
- [ ] Existing profiles load with the display fallback and unchanged permissions/paths; corrupt metadata is rejected, not reset.
- [ ] Duplicate/reserved/malformed IDs, invalid display input, invalid setup and concurrent creation fail with typed errors and no orphaned runnable profile.
- [ ] Activating pickup remains an explicit authorized operation; pause never claims to stop active jobs.
- [ ] A readiness result identifies the checked configuration revision and time; stale/unverified is distinct from invalid.
- [ ] Admin mutation/CSRF guards apply; Dev cannot create or change identity through direct API requests.
- [ ] Setup never accepts secret values in place of supported credential references.

## Verification
Happy path and negative tests at profile/config/worker boundaries, including concurrent visibility and rollback. Fake all forge/runtime commands. Cover stable-ID behaviour across memberships, operations and existing serialized profile fixtures; document any storage compatibility change without silently changing runtime state schema 1.

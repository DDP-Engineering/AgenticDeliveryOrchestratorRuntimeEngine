# [Web UX] Record structured redacted change evidence and build useful audit history

## Tracking
Work item: W15. Priority: P2. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [W02 #6](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/6), [W06 #10](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/10), [W09 #13](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/13), [W14 #18](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/18).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
Current audit actions and compact key details cannot explain exactly what changed or whether a candidate was only prepared or applied. Capture structured evidence at the server mutation boundary.

## Scope
Events: actor, time, stable project/resource identity, action, result, operation correlation, base/candidate revisions and redacted before/after where actually known. Distinguish prepare/apply/discard from config, user access, enrollment/import/clone and pickup operations.
Record committed mutation evidence consistently with the owning transaction/operation; explicitly define rejected-operation and crash/replay semantics. Idempotent async completion cannot duplicate an applied event.
Existing history remains readable with Before value not recorded when absent; do not fabricate historic differences. Any web DB upgrade must be explicit, atomic and reject corruption/unsupported schema; do not migrate earlier runtime state.
UI filters actor/project/type/period with server paging. Show Who changed what, when and result; move retention policy to administrative settings with a clear impact summary.

## Acceptance criteria
- [ ] Relevant successful changes carry truthful before/after and result, while preparation never looks applied.
- [ ] Secrets/passwords/environment values cannot leak through nested diffs, errors, correlation or actor metadata.
- [ ] Failed/rolled-back operations cannot leave an audit event claiming successful application; crash/replay semantics are tested.
- [ ] Existing events remain interpretable and missing values are explicitly unrecorded.
- [ ] Authorized filters/counts/paging are correct; Dev cannot access administrator history or infer unassigned project events.
- [ ] Retention changes preserve separate bounds and make deletions/limits clear; policy editing remains admin-only.
- [ ] Corrupt/unsupported audit storage fails closed without reinitializing identity or audit.
- [ ] UI and exports, if any, use redacted server projections.

## Verification
Offline success/prepare/apply/discard/import/access diffs, secrets, rollback/crash/replay, legacy history, schema corruption, filter/paging and RBAC tests. Browser scannability, empty/error and retention-policy separation.

## Code and documentation orientation
web/store.py audit schema/retention, web/app.py mutation/audit projections; Administration and project History pages; test_web_storage.py, config/access/import tests; Component_Web_Identity/API/Frontend docs.

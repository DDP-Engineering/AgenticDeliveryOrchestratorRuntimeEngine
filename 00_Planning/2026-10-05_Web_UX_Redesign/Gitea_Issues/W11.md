# [Web UX] Present scoped statistics and per-job consumption with honest coverage

## Tracking
Work item: W11. Priority: P2. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [W01 #5](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/5), [W07 #11](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/11), [W10 #14](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/14).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
Users need to understand consumption per job/project/period without reconciling differently scoped sections. Build the statistics experience on the new explicit metrics contract.

## Scope
Persistent scope bar: authorized projects, period, timezone and grouping. Every card/chart/table/export uses this scope. Initial cards: started/completed/failed jobs, known input/output/total tokens, durations and measurement coverage; financial cards only for admin.
Provide trend, project and job breakdowns; quality/recovery becomes secondary detail. Job detail/list consumption distinguishes lifetime from selected-period numbers. Show sample sizes and metric definitions where needed.
Display message series as Not available until the real message contract lands; never substitute launch counts. Avoid zero cards while loading or after request failure.

## Acceptance criteria
- [ ] Changing period/project/timezone updates all scoped presentations and export together; stale requests cannot overwrite a newer scope.
- [ ] All-time is selected explicitly; active-now is clearly separated from interval events.
- [ ] Known zero, missing usage and incomplete coverage use different labels; monetary estimates are distinct from reported cost.
- [ ] Every per-job value identifies the project and whether it is lifetime or in-period.
- [ ] Dev sees allowed projects and nonfinancial statistics only, including direct routes and export links.
- [ ] Date-boundary/timezone hints match the backend semantics.
- [ ] Charts have readable labels and an accessible tabular equivalent; empty/error states and 390px layout work.
- [ ] Message placeholders state availability rather than fabricated counts.

## Verification
Helper aggregation/scope tests and offline browser project/period/timezone changes, out-of-order responses, absent/zero measurements, CSV scope, role restrictions, keyboard and chart-table parity. Use deterministic data, not screenshot-only validation.

## Code and documentation orientation
Frontend Metrics pages/helpers/i18n; job consumption presentation; filtered export UI; frontend helper tests and offline E2E; Component_Web_Frontend and user statistics docs.

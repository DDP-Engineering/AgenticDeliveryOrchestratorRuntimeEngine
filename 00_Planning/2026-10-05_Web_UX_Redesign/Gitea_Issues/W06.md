# [Web UX] Implement portable settings import and settings-based project cloning

## Tracking
Work item: W06. Priority: P2. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [W03 #7](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/7), [W05 #9](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/9).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
Users need to copy known rules without accidentally duplicating another project's state, repository identity or permissions. Add portable import and clone as explicit new-project enrollment methods.

## Scope
Reuse the portable schema/allowlist for both file import and copying an authorized source project's settings. Flow: source -> recognized rules/exclusions -> new identity/repository/host paths -> environment/reference reconfirmation -> validated review -> create with pickup stopped.
Show Source value / This server's value / Effect. Allocate independent owned locations and stable project ID; existing repository cloning is not performed. Reconfirm credential/endpoint references explicitly.
Bind confirmation to source-file/source-config revision and target candidate. Reject stale source, incompatible settings and ambiguous ownership. Never mutate the source project.
Import into an existing project and multi-field replacement are outside this ticket; do not disguise them as enrollment.

## Acceptance criteria
- [ ] Admin can create a new project from a supported package or source project; only portable fields transfer.
- [ ] New project receives independent identity/state/worktree/metrics paths and starts with pickup stopped.
- [ ] No users/grants, jobs, history, audit, pending configuration, secrets or source resource ownership are copied.
- [ ] Mapping/reconfirmation is visible and required; invalid/overlapping target paths and unresolved references prevent creation.
- [ ] Source revisions changing after review cause a typed conflict, with a re-review action.
- [ ] Unknown/incompatible fields fail closed; no partial profile remains after failure or duplicate confirmation.
- [ ] Both UI and API enforce admin authorization and CSRF; source permissions are rechecked at confirmation.
- [ ] Exact TOML enrollment remains an unchanged-copy advanced option with separate wording.

## Verification
Offline import/clone happy paths and negatives for source mutation, missing source, schema/version, secrets, target identity/path collisions, rollback, replay/double-submit and Dev denial. Browser review/change/back and explanatory exclusion scenarios.

## Code and documentation orientation
Portable-settings module and web/app.py preview/create operations; enrollment wizard method branches; profile/config tests and offline E2E; Component_Web_API/Frontend/Profile docs.

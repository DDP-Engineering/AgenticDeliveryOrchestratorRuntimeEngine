# [Web UX] Expose an authorized global job read model with actionable evidence

## Tracking
Work item: W07. Priority: P1. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [BASE #4](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/4).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
Current job listings are project-scoped and the compact view omits ticket titles and detailed waiting evidence. A global UI must not concatenate incomplete per-project pages or infer actions from a stage label.

## Scope
Provide server-authorized global/project job listing with deterministic pagination, search and simple status groups. Identity is (project_id, run_id); identical run IDs in two projects must not collide.
Expose lifecycle, exact AEGIS stage, outcome, persisted last activity, safe ticket/MR URL and available ticket title, wait reason, responsible role/person and evidence location. Do not invent titles, questions, named reviewers or outcomes. Old jobs without new metadata use honest fallbacks.
Prefer persisted snapshots/read models; no forge fetch per refresh. Add optional evidence only with an explicit compatibility analysis of schema-1 state/journals; never reset old/corrupt state.
Consumption is added by the statistics contract later; if currently unavailable return an explicit unknown rather than zero. Reject corrupt evidence with typed errors and make completeness explicit instead of silently presenting partial totals.

## Acceptance criteria
- [ ] Admin sees all authorized jobs; Dev sees only assigned projects in listing, search, counts and direct details.
- [ ] Paging/filter/search is global, stable and complete under the documented snapshot/order semantics.
- [ ] Cross-project run-ID collisions, missing timestamps/titles and archived-project cases are handled explicitly.
- [ ] Waiting states identify next action only from real evidence; unknown evidence remains unknown.
- [ ] Unsafe/malformed URLs and corrupt persisted input fail closed without secret leakage.
- [ ] List totals cannot silently omit failed project reads and claim completeness.
- [ ] Refresh performs no live forge requests, executor launches or container operations.
- [ ] Existing project-scoped API clients continue to work or receive an explicitly versioned contract change.

## Verification
Offline multi-project paging/search, RBAC direct-route/count leaks, tie ordering, source changes, missing metadata, URL validation, corrupt state/journal and duplicate run-ID tests. Verify command runner is not called while reading views.

## Code and documentation orientation
web/app.py run views/paging, persisted run/journal evidence, metrics where reused; state/orchestrator only for necessary optional evidence snapshots; test_web_paging.py, test_web_rbac.py, state tests; relevant component docs.

## Agent implementation contract
Read repository AGENTS.md, the full .agentic/AGENTS.md, relevant context and component contracts before product implementation. Use AEGIS for code, tests and implementation validation, with its resolved interaction mode and checkpoints. Ticket creation and standalone planning do not use AEGIS.
Start only after native blockers are closed, explicit decision gates are satisfied and the operator authorizes pickup. Never treat label priority or issue closure as publication approval.
Bound each run to at most four hours, three fix/review cycles and twenty hand-authored changed files (generated static output tracked separately); record an explicit cost/executor budget before launching executors. If the scoped work exceeds a bound, report/split rather than silently expand it.
Every public behaviour needs a happy test and negative trust-boundary tests. Keep unit tests offline, fail closed on corrupt input, preserve CSRF/RBAC/secret redaction, forge/executor/runtime independence and draft-only publication. No merge.
Update affected 05_SoftwareDocu component pages from the template, implementation-facing/operator docs, applicable AEGIS knowledge and CHANGELOG.md in the same change. Preserve license headers and Code_Style.md conventions. No speculative version bump or new dependency without a scoped justification.
For verification use the published baseline instructions: from 04_Software, uv run pytest and uv run ruff check .; from 04_Software/web, npm run typecheck, npm run build and npm run validate.

# [Web UX] Define and export a versioned portable project-settings package

## Tracking
Work item: W05. Priority: P2. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [W02 #6](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/6).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
The existing TOML import is host-specific and metrics CSV export is not settings export. Introduce a portable package for transferring allowed working rules, with a contract shared by clone and import.

## Scope and chosen defaults
Use a versioned JSON envelope with explicit kind=adore-project-settings and schema_version=1. Include only an enumerated allowlist of portable, validated configuration fields; document that list and compatibility rules before implementation. Default to creating a new project on import.
Exclude profile/display identity authority, repository/branch ownership, absolute state/worktree/metrics paths, jobs/history, users/grants, audit, pending revisions, secret values and financial price history. Any exported nonsecret credential/endpoint reference is marked requires reconfirmation; never assume the same reference is valid on another server.
Provide an admin-only download with a preview/description of included/excluded data. Export from the validated authoritative config, not a best-effort redacted object. A checksum detects changes but is not claimed to authenticate an untrusted package.

## Acceptance criteria
- [ ] Exported packages have deterministic version/type semantics and a documented allowlist; importing the export reproduces portable values only.
- [ ] Secrets and excluded identity/state/access data are absent even when nested or placed in unexpected configuration fields.
- [ ] Unknown keys/versions/types, duplicates if the parser accepts JSON duplicate keys, invalid limits and malformed nested values are rejected with typed errors.
- [ ] Explicit source compatibility is checked; unsupported fields are not silently ignored or guessed.
- [ ] Dev/non-admin/invalid-session requests cannot export settings or discover unauthorized project metadata.
- [ ] Existing exact TOML import and metrics CSV exports remain distinct and compatible.
- [ ] No unsupported runtime state migration or separate hardcoded release version is introduced.

## Verification
Offline round-trip happy path plus schema, corruption, secret leakage, nested exclusions, bad credential references and RBAC negatives. Document the format and operator limitations in English in the same change.

## Code and documentation orientation
Validated config/settings catalog, web/app.py and a scoped portable-settings module if appropriate; profiles and credential-reference boundaries; new portable contract tests; Component_Config/Web_API docs.

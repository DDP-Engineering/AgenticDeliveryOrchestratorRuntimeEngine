# [Web UX] Introduce the accessible dashboard shell, branding and plain-language vocabulary

## Tracking
Work item: W01. Priority: P1. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [BASE #4](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/4).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
The current application mixes broad navigation, technical terms and inconsistent visual scope. Introduce the shared shell and reusable presentation primitives that later flows consume.

## Scope
Keep React/TypeScript/Vite and existing route semantics. Extract page-level components incrementally, without a wholesale framework replacement. Implement Overview/Projects/Jobs/Statistics navigation; contextual project subnavigation; admin navigation and account/preferences. Use clear headings, visible scope, one main contextual action, accessible status labels and progressive disclosure.
Integrate the approved DDP Engineering transparent sage mark on the dark navigation background without a white rectangle; preserve the custom logo proportions. ADORE remains the product label. The source asset must come from the bootstrap reference bundle.
Define English copy for job, enrolled project, pickup stopped, waiting for clarification, waiting for approval and draft review. Preserve supported localization catalogs and theme preferences; do not copy hardcoded Romanian prototype text into production.

## Acceptance criteria
- [ ] Main routes and browser Back/deep links continue to work; project context is visible and preserved deliberately.
- [ ] Admin and Dev navigation reflect their server-authorized capabilities; a Dev with no grants gets a useful empty state.
- [ ] The logo has no pale backing panel and scales without distortion at desktop and 390px width; both themes remain readable.
- [ ] State is conveyed with text/icon as well as colour; essential field instructions are visible, not placeholder-only.
- [ ] Keyboard navigation, visible focus and semantic headings work across shell navigation.
- [ ] Loading, no records and failed requests have different presentations; failed requests do not show false zero totals.
- [ ] No new UI control promises an unsupported approval, merge, clone or job pause operation.

## Verification
Frontend helper/type/build checks plus offline browser navigation, roles, missing-data/error, both-theme and narrow-viewport scenarios. Preserve existing route/i18n regression coverage. Inspect representative screenshots; do not claim full WCAG compliance from automated checks alone.

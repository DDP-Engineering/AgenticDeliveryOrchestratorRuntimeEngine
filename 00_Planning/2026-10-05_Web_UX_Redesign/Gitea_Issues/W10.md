# [Web UX] Make statistics scope, per-job usage and measurement coverage consistent

## Tracking
Work item: W10. Priority: P2. Parent: [EPIC #3](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/3).
Dependencies: [BASE #4](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/4).
Implementation baseline: task/adore-web-interface; bootstrap records the remotely available commit. New specs/docs and acceptance copy are English.

## Problem and target behaviour
All-time totals and period aggregates coexist under date controls, and absent consumption can look like zero. Establish one explicit scope for every measure and export.

## Scope and metric definitions
Scope is authorized project set + interval + IANA timezone + granularity. Use a documented half-open instant interval [from,to), with date controls translated to local-midnight boundaries; handle DST correctly.
Started/completed/failed counts use their own lifecycle event times. Active now is a separate current-state stock. Token/cost totals are attributed by event consumption time, not job start time. Per-job lifetime and in-period consumption are distinct fields identified by (project_id,run_id).
Unknown/unreported tokens or cost are null/unavailable with coverage, not measured zero. Reported and estimated costs remain separate and admin-only. Missing/invalid timestamps are counted as unallocated, never guessed into a date bucket. Rates/durations expose denominator/sample definitions.
Reuse compatible existing aggregates, add the missing contract and filtered CSV semantics. Do not migrate/reset runtime state or relabel executor launches as messages.

## Acceptance criteria
- [ ] All scoped cards, tables, charts and CSV use the same project/period/timezone definitions; all-time is an explicit scope.
- [ ] Cross-period jobs contribute consumption to each actual event period and lifecycle counts to their own event timestamps.
- [ ] All missing data, measured zero, unavailable date attribution and failed load are distinguishable.
- [ ] Cost redaction holds on every admin/developer endpoint/export, including new per-job projections.
- [ ] Replay/deduplication, same run ID in two projects, boundary dates and DST do not double count or leak scopes.
- [ ] Invalid filters/timezones/ranges, corrupt timestamps/events and unknown persisted schema fail with typed errors.
- [ ] Rates and mean/median durations match documented samples rather than approximate browser filtering.
- [ ] Current-stock values are not mislabeled period totals.

## Verification
Offline analytical fixtures with hand-calculated expected counts/tokens, cross-midnight/DST, interval boundaries, missing timestamps, absent versus zero usage, replay, costs, CSV and RBAC negatives. Include source-coverage assertions and preserve price-history semantics.

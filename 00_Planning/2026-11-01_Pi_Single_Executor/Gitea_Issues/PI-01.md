# [Pi] Spike: confirm Pi 1.x headless contracts before integration

Labels: P1, enhancement. Part of [epic #50](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/50). Depends on: nothing.
Needs the owner present: real credentials are used interactively and never written to files.

## Goal

Answer, with observed evidence, every question below about Pi 1.x so the
implementation tickets (PI-02 to PI-07) build on facts, not assumptions. Pick the
exact versions ADORE will pin. **No product code changes in this ticket.**

## Needs from the owner

- An API key for at least one provider (for example OpenAI or Anthropic).
- A ChatGPT Plus/Pro account for the sign-in questions.
- LM Studio or Ollama running and reachable, with one model loaded.
- Docker, and Node at the version Pi requires (expected >= 22.19).

## Questions

1. **Install**: package name and latest 1.x version; Node minimum; installing into
   an isolated prefix (`npm install --prefix`); size; Linux container and Windows.
2. **RPC protocol** (`pi --mode rpc --no-session`): how a prompt is sent; the event
   sequence of a run; how completion is signalled (`agent_end`, `agent_settled`);
   `abort` behaviour and timing; error events; exit codes; stderr usage. Write a
   minimal Python client `rpc_probe.py` and record a full event log of a short
   coding task (redacted) as a fixture for PI-02 tests.
3. **Usage and cost**: where tokens (input, output, cache read/write) and cost
   appear per turn and in `get_session_stats`; whether cost is a Pi estimate.
4. **Isolation**: can the agent directory (`~/.pi/agent`) be relocated by an
   environment variable or flag? Can `auth.json` live in a different directory
   from settings and `models.json`? Everything Pi reads from the user's home and
   from the project (`AGENTS.md`, `.pi/`, skills, extensions, prompts) and how to
   disable personal resources.
5. **Trust and extensions**: does an RPC run load project-local resources without
   an interactive trust prompt? What do `--approve`/`--no-approve` do? How to load
   an ADORE-owned extension explicitly (flag or settings)? Show that an extension
   can block `git push` and `gh`/`glab`/`tea` commands in RPC mode.
6. **Providers**: the providers usable with an API key and the exact environment
   variable for each; how to pass a key without a file; the `models.json` schema
   for an OpenAI-compatible endpoint (API types, base URL, model id, key) proven
   against LM Studio or Ollama, including from inside a container.
7. **ChatGPT sign-in**: can Pi's official OpenAI login (`/login openai`) run outside
   the TUI (RPC command, CLI flag, or a scripted TUI) on a machine without a
   browser? Where is the credential stored and what does it contain (host ID,
   refresh token)? Is concurrent use by two Pi processes safe (lock)? Does a
   credential directory mounted into a container keep refreshing correctly?
   What happens when the refresh fails?
8. **Web access** (`pi-web-access`): pinned version; installing it so headless runs
   load it; its configuration file and keys; Exa without a key; Brave or Tavily
   with a key; `fetch_content` limits; behaviour without network.
9. **Windows**: Pi installed on Windows (PowerShell tool, Node path, quirks).
10. **Failure modes**: invalid key, unreachable endpoint, unknown model, rate limit,
    no network: which events and exit codes ADORE will see.

## Deliverables

In `00_Planning/2026-11-01_Pi_Single_Executor/`:

- `SPIKE_FINDINGS.md`: one section per question with the command, the observed
  output (secrets redacted) and the consequence for PI-02 to PI-07; a table of
  pinned versions (Pi, `pi-web-access`, Node); a list of changes the plan needs.
- `rpc_probe.py` and the recorded event logs (`fixtures/*.jsonl`, redacted).

If a finding contradicts a decision in `PLAN.md`, list it under "Plan changes
needed" and ask the owner; do not edit the plan's decisions yourself.

## Acceptance criteria

- [ ] Every question is answered with evidence, or marked impossible with the
      command and output that show it.
- [ ] Pinned versions recorded; the RPC fixture covers a run with tool calls,
      usage events and a clean end, plus one aborted run and one failed run.
- [ ] No product code, configuration or tests changed.
- [ ] No keys, tokens, account e-mails or host IDs in any committed file.

# [Pi] Live acceptance, documentation audit and backlog cleanup

Labels: P1, change. Part of [epic #50](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/50). Depends on: [PI-03 #53](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/53), [PI-04 #54](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/54), [PI-05 #55](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/55), [PI-06 #56](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/56), [PI-07 #57](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/57).
Needs the owner present: real credentials, a test repository and a forge account.

## Goal

Prove end to end that ADORE with Pi works with real providers, make the
documentation consistent, and close what the epic made obsolete.

## Scenarios

Run a real ticket through to a draft PR/MR on a test repository for each row:

| Where | Credential | Internet |
|---|---|---|
| Container | API key (one provider) | Off |
| Container | API key | On (task needs a library download) |
| Container | OpenAI-compatible endpoint (LM Studio or Ollama) | Off |
| Container | ChatGPT subscription | Off |
| Server (Linux) | API key | n/a |
| Server (Windows) | API key | n/a |

Failure checks: invalid key, endpoint down, ChatGPT signed out (refresh failure),
stage timeout (abort), cancellation.

## Scope

In: the runs above with evidence; a documentation audit of the changed areas (the
`documentation-audit` skill if your agent has it, otherwise a manual pass over help,
`01_Documentation`, `05_SoftwareDocu`, knowledge and requirements); fixes for
documentation inconsistencies found; checking that the tickets closed as
superseded on 2026-11-01 (#43, #45, #46, #33, #44, #32, #34) are really covered,
and reopening any that is not.

Out: product changes beyond small fixes found during acceptance; anything larger
becomes a new ticket.

## Deliverables

`00_Planning/2026-11-01_Pi_Single_Executor/ACCEPTANCE.md`: date, ADORE commit, Pi
and `pi-web-access` versions, each scenario with result, PR/MR link, tokens and
duration, and every failure with its follow-up ticket.

## Acceptance criteria

- [ ] Every scenario passed, or its failure has a follow-up ticket.
- [ ] Documentation audit clean, or findings fixed or ticketed.
- [ ] Every ticket closed as superseded is confirmed covered, or reopened with a reason.
- [ ] No secrets, account e-mails or host IDs in `ACCEPTANCE.md`.

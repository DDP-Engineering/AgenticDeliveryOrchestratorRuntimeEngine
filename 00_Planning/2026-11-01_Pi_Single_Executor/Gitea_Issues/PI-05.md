# [Pi] Sign in with ChatGPT from the ADORE web interface

Labels: P1, enhancement. Part of [epic #50](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/50). Depends on: [PI-04 #54](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/54).

## Goal

An administrator signs the ADORE server into a ChatGPT Plus/Pro account once, from
the web interface. Projects whose provider is "ChatGPT subscription" then run Pi on
that subscription, in containers and on the server, without anyone copying files.

## Decisions

- Pi's official OpenAI flow ("Sign in with ChatGPT"), run as the spike showed for a
  machine without a browser: ADORE shows the authorization link, the administrator
  opens it on their own computer and pastes the redirect URL back into ADORE.
- The legacy Codex-client flow (`openai-codex`) is not offered.
- One credential per ADORE host, in an ADORE-owned directory. It is used in place:
  mounted into containers (only that directory), never copied, so Pi's own lock
  serializes token refreshes and the host keeps one host ID.
- Disconnect deletes the credential. Sign-in and disconnect are admin-only, need
  CSRF, and are audited without any token value.

## Scope

In: backend routes to start sign-in, complete it with the pasted URL, show status
and disconnect; the Settings interface (four locales, help); credential directory
and container mount; status values signed in / not signed in / sign in again
(refresh failed, for example `invalid_grant`); clear errors for OpenAI refusals
(`subscription_sharing_user_not_eligible`, usage limits); readiness check.

Out: API-key providers and endpoints (PI-04), internet switch (PI-06).

## Where to look

`adore/web/app.py` (credential and executor routes), `adore/web/executor_settings.py`,
container start in `adore/isolation.py` / `adore/execution.py`,
`web/src/ExecutorCredentials.tsx`, `01_Documentation/Security_And_Credentials.md`.

## Acceptance criteria

- [ ] Admin-only and CSRF-protected; developers get 403; audit rows contain no
      tokens, codes or redirect URLs.
- [ ] Status is shown correctly for all three states (offline tests with a fake Pi
      and fake credential files).
- [ ] Two concurrent jobs on the same credential do not corrupt it (fake-process
      test; one live check recorded in the PR).
- [ ] Containers mount only the credential directory, read-write; no other host path.
- [ ] Refusals and refresh failures show a clear sentence in four locales.
- [ ] `Security_And_Credentials.md`, help, `CHANGELOG.md` and release note updated,
      including that ADORE is free today and that offering it hosted or paid would
      first need OpenAI's interest form.

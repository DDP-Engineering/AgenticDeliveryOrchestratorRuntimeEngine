# [Pi] Run Pi through its RPC mode in the executor image

Labels: P1, enhancement. Part of [epic #50](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/50). Depends on: [PI-01 #51](http://192.168.1.15:3001/dpasare/AgenticDeliveryOrchestratorRuntimeEngine/issues/51).

## Context

Today ADORE runs `pi -p --mode json --model {model} {prompt}` with Pi 0.80.3
(`04_Software/docker/Dockerfile.executor-base:25`). The Pi launcher is
`PiExecutor` in `04_Software/adore/executor/launcher.py` (about lines 433-512).
Headless Pi only loads its project guard after the project is trusted, which ADORE
does not handle. Token usage is parsed from the captured output.

## Goal

The executor image ships the pinned Pi and `pi-web-access` from `SPIKE_FINDINGS.md`,
and ADORE drives one `pi --mode rpc --no-session` process per stage.

## Decisions

- RPC mode, not the SDK and not `-p --mode json`.
- One fresh process per stage, cwd = worktree, ADORE-owned agent directory inside
  the container (no personal resources).
- The push/forge guard is an ADORE-owned Pi extension loaded explicitly (method from
  the spike); it must not depend on project trust.
- Usage is journaled per turn as versioned usage events (same shape that
  `adore/metrics.py` `unique_usage_events` validates); Pi's cost is an estimate, so
  keep today's semantics: tokens recorded, cost not reported as billed.
- Memory stays bounded: never keep the whole event stream; keep a bounded tail for
  evidence (`adore/util.py` `output_tail`).

## Scope

In:
- Dockerfile and `docker/verify-runtime.sh`: pinned Pi, `pi-web-access`, Node version.
- New module `04_Software/adore/executor/pi_rpc.py`: start, send prompt, read JSON
  lines, detect completion, `abort` on stage timeout or cancellation marker, then
  terminate after a grace period; map failures to ADORE's existing failure codes.
- `PiExecutor` uses `pi_rpc`; the guard extension and trust handling as above.
- Tests with a fake Pi RPC process that replays the spike fixtures.

Out: removing other executors (PI-03), provider and endpoint settings (PI-04),
ChatGPT sign-in (PI-05), internet switch (PI-06), server-installed Pi (PI-07).

- [ ] New offline tests (`tests/test_pi_rpc.py`) cover: successful run with tool

      very large output with bounded memory.

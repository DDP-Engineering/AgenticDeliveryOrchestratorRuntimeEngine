## Frame

Problem: Project details > Configuration lists about 100 settings, but only
  the 10 common settings have help of their own; every other row's Help says
  "See the configuration reference for the meaning and accepted values of this
  setting." The user: "the help messages are not edificatory for the project
  settings". Some existing help is also imprecise (concurrent jobs reads as
  parallel runs, while the reference says it does not enable parallel
  conduction), and no row tells the ADORE default value behind a Default badge.
Desired outcome: each setting's Help explains in the user's language what the
  setting controls, its unit or allowed values, and the effect of changing it,
  and shows ADORE's default value.
Actors: administrator deciding what to change; developer reading a project's
  settings.
Primary scenario: user opens Configuration -> expands Help on
  `recovery.max_stage_failures` -> reads what a stage failure is, what happens
  when the limit is reached, the allowed range and "ADORE default: 3".
Examples: `polling.max_concurrent_runs` explains it caps persisted working
  runs and does not run jobs in parallel; `delivery.draft` explains drafts are
  always used (false is refused); `container.egress.mode` lists open, none and
  allowlist-proxy with their effect.
Counterexamples: secret-like keys stay hidden; help never shows another
  project's values.
In scope: help text per effective setting in EN/FR/DE/RO, corrected common
  help, ADORE default value per setting from the API, a coverage test that
  every setting has help in every locale, docs.
Out of scope: changing setting behavior, validation or editability; the
  configuration reference rewrite (it stays the long-form source).
Constraints: four locales (REQ-UX-749d37c8); texts must match the actual code
  behavior (config.py, orchestrator, isolation); no secret values; existing
  settings metadata and row editing unchanged.
Success signals: automated tests show every effective setting key has help in
  every locale and the API returns defaults; browser check shows specific help
  and defaults.
Evidence:
  - STATED: user message above; user chose to do this before TASK-3922c5e8.
  - OBSERVED: `04_Software/web/src/settings.ts` COMMON_SETTINGS (10 keys with
    label/help); `App.tsx` SettingsList Help shows the type line plus
    `row.help` or `settingGeneralHelp`; `i18n.ts` holds the 10 help texts.
  - OBSERVED: `01_Documentation/Configuration_Reference.md` has short entries
    for many keys ("Base loop interval."); `adore/config.py` dataclasses define
    every key and default; `Config()` defaults are available in Python.
  - OBSERVED: `settingHelpConcurrent` = "Maximum number of project jobs in
    flight at once." vs reference "Capacity ceiling for persisted working runs;
    it does not enable parallel conduction".
  - INFERRED: the API can return each setting's default from a default
    configuration, so the default shown never drifts from the code.
Assumptions: about 100 effective keys (plus per-executor command entries)
  need texts; per-executor command fields share one text per field name.
Unknowns: none blocking beyond Q1.
Decision-blocking questions:
  - Q1: help texts for all settings in all four languages, English-only texts,
    or editable settings only?
Proposed behaviors:
  1. Every setting's Help states what it controls, its unit or allowed values
     and the effect of changing it, in the selected language.
  2. Help shows ADORE's default value for the setting, taken from the code.
  3. A test fails when a setting has no help text in any locale.
Path and reason: full - new texts for every setting and a new API field.

## Design

Behavior lives in `specs/REQ-UX-b0e9a434.md`.

- **Defaults (REQ-FUNC-c6c71dbd).** `adore/config.py` gains public
  `default_config()` (a `Config()` completed by `_derive_names`), so the web
  layer does not reach into a private helper. `adore/web/app.py` builds the
  redacted default mapping once and `_setting_metadata` adds `default` by
  looking up each setting's `key` (null when absent).
- **Catalog (REQ-UX-b0e9a434).** `web/src/settingKeys.json` (sorted array).
  New `tests/test_web_setting_catalog.py` derives the expected keys from the
  leaves of `config.example.toml`, of `default_config()` and of an example
  with stage timeout overrides, replaces variable segments with `*` and adds
  the bare map keys; it must equal the JSON.
- **Texts.** New `web/src/settingHelp.ts` with `SETTING_HELP` for en/fr/de/ro
  keyed by catalog key and `settingHelp(key, locale)` (exact, then `*`
  pattern by segment). Texts are written from config.py, the configuration
  reference and the reading code; reserved settings say so. The 10 common
  settings use the same texts (single source); i18n keys that only the
  removed help used are deleted, those the Add project form uses stay.
- **UI.** `settings.ts` rows carry `defaultValue`; `SettingsList` takes the
  locale and shows type line, `settingHelp(...) ?? t("settingGeneralHelp")`
  and `t("settingDefaultValue")` with the formatted default
  (`t("settingNoDefault")` for null). COMMON_SETTINGS keeps labels and kinds,
  drops its help keys.
- **Tests.** pytest: catalog sync, API defaults (in test_web_config.py);
  node: `web/tests/settingHelp.test.mjs` (coverage per locale, no stray
  keys, pattern resolution), settings.test.mjs (defaultValue); manual
  browser check.
- **Compatibility.** Additive API field; no config, data or behavior change.
- **Alternatives rejected.** English-only or editable-only texts (RULING-002);
  parsing the Markdown reference at runtime (too terse, not localized).
- **Risks.** Texts can drift from later behavior changes; the catalog test
  only guarantees presence (spec assumption). No structure change beyond two
  frontend data modules; no architecture drawing owed.
- **Expected files.** `04_Software/adore/config.py`, `04_Software/adore/web/app.py`,
  `04_Software/tests/test_web_config.py`, `04_Software/tests/test_web_setting_catalog.py`,
  `04_Software/web/src/{settingHelp.ts,settingKeys.json,settings.ts,App.tsx,i18n.ts}`,
  `04_Software/web/tests/{settingHelp.test.mjs,settings.test.mjs}`, built
  static assets, `01_Documentation/Web_Interface.md`,
  `05_SoftwareDocu/Component_Web_API.md`, `05_SoftwareDocu/Component_Web_Frontend.md`,
  `.agentic/knowledge/web-interface.md`, `CHANGELOG.md`.

### Interfaces and data

- INFERRED — **D5 native verification-only operation** (REQ-PLAT-a39ffa22, REQ-SEC-d94baaf1, REQ-SEC-c81de547; RULING-002): add `LocalTarget.run_verification(command: str, *, timeout: float) -> CommandResult`, called only by configured-direct validate. It requires a nonempty single-line NUL-free string matching the backend's configured `workflow.verify_command`; invalid/unconfigured/mismatched requests raise `LocalExecutionError` before launch. Verify pinned resource/account/environment, select `/bin/sh -c <command>` on Linux or absolute native `SystemRoot/System32/cmd.exe /d /s /c <command>` on Windows, with SystemRoot from the bound account environment, never project PATH/COMSPEC. Require an installed regular executable, pass the complete command as one shell argument and use the existing controller at the worktree root with bound environment and validate timeout. Ordinary resolver/run_files/callable shell refusal and wrapper refusal are unchanged; the trusted ownership supervisor is not an interpreter-wrapper shell bypass.
- INFERRED — **D6 execution/output** (REQ-PLAT-125bc4c1, REQ-DATA-72e08277, REQ-REL-4deb6eed, REQ-REL-50474528): containers reuse `_execute(run)(["sh", "-c", command], timeout=limit)` with no new container operation; native uses D5. `limit` is `stage_timeout_overrides.get("validate", per_gate_timeout_seconds)`, independent of build timeout. Add an opt-in native controller tail-capture keyword, default false, and a local verification drain helper in `local_process.py`: continuously strict-decode UTF-8, redact known secret values and credential forms across read boundaries before eviction, and keep at most 64 KiB per stream of the actual end, not a prefix. Redaction retains matching overlap/token state so a split/overlong secret never leaks as an orphan suffix; cap unfinished lines/tokens and drain all bytes. Existing prefix-mode AEGIS/preparation capture and their 4 MiB/64 KiB contracts remain untouched. All outcomes retain release-before-execution, owned timeout interruption, descendant drain and typed cleanup refusal; no new unsupervised subprocess or preparation-runner change.
- INFERRED — **D7 durable evidence/integrity** (REQ-DATA-72e08277, REQ-REL-4deb6eed, REQ-FUNC-ff7dad34): keep `summary`, `implementation` and `changed_files` in the existing object. Unconfigured remains `verification="not configured"` with no result. Configured uses `verification="passed" | "failed" | "timed out"` and `verification_result={command, exit_code, seconds, timed_out, output}`. `command` is sanitized retained text, `seconds` is monotonic elapsed time; strict types reject boolean exits, nonboolean timeouts, nontext streams/fields, negative/nonfinite duration, status/result disagreement, missing/unknown result keys or over-bound saved output. Use a conductor parser raising `StateError` for corrupt saved evidence and `IsolationError` for malformed new outcomes; catch typed refusals at direct conduction/approval/publication boundaries and record failure, never downgrade them to unverified. `state.py` and top-level schema stay unchanged; no format repair/reader/migration.
- INFERRED — D7 output composition (REQ-DATA-72e08277, REQ-FUNC-e5899386): combine stdout followed by stderr, inserting one newline only when necessary to separate nonempty streams; chronological interleaving is not claimed. Apply target known-value redaction plus existing `_sanitize(..., None)` through `output_tail(..., lines=200, chars=_MAX_EVIDENCE)` before retention. Sanitize command separately under the existing character bound. Native streaming capture must apply equivalent credential masking before rolling eviction, not rely on post-cut regex. Store timeout as the boolean and status, and render the words `timed out` in context/result text without displacing actual output lines. Latest result replaces only the prior result, not completion/summary; pass after failure exposes the pass.
- INFERRED — D4 failure durability (REQ-REL-465c51f3, REQ-REL-63496e9f, REQ-FUNC-e969d30e): for failure, set the new result, clear completion/candidate binding and route `stage="build"` in memory before `_stage_failure` performs its count/history/state save. The saved incident still names validate. Thus remediation cannot replay stale completion after reload; at direct admission, an already-exhausted verification failure cannot launch again even if interruption occurred during required notification/terminal handling. Preserve last result through build/clarification until another verifier outcome. Terminal `VERIFICATION_FAILED` keeps evidence; unchanged explicit Retry re-arms the count and then launches a fresh build under cumulative budgets. A checkpoint failure after a pass retains validate completion; Retry may rerun independent verification without another Pi launch, never reuse a pass across integration/drift. Keep no-progress and executor/notification/budget precedence from DW-02.
- INFERRED — **D8 candidate/presentation** (REQ-FUNC-bea4c0aa, REQ-UX-0d63ca91, REQ-UX-50f9bf53, REQ-FUNC-ff7dad34): a single typed evidence reader feeds readiness and the shared direct body. Configured approval says validated, not unverified; show sanitized command in a literal code block safe for embedded backticks, result/exit/duration and retained output. Both approval and create/adopt/revise bodies use that reader after reload. Final checkpoint and clean fingerprint follow verification; retain the integrated target identity and refuse target drift during validation, and keep existing pre-publication candidate/target freshness checks. Drift invalidation removes configured pass authority and requires integration, a new command result and fresh approval. Summary alone never passes. No forge adapter, merge policy or executor publication authority changes.

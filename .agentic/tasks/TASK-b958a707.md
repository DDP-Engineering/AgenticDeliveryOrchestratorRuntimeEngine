## Design

settings.ts owns exact overrides before section fallbacks and explicit hidden/read-only technical keys; the existing row/catalog transport stays decisive. SettingsList groups clarification, recovery, stage overrides and statistics paths with native closed disclosures and uses one target-branch row with a local PR/MR link that opens Repository. Existing Executor configuration, credential forms and external preparation notice retain their responsibilities. No backend changes or persistence migration; native links/disclosures retain keyboard behavior. Unknown visible keys fall back to Technical details; externally owned container/local/execution fields stay outside Settings. Existing worktree fields are shown read-only under server authority. Inactive GUI settings are hidden without deleting CLI schema. No component structure change; current architecture remains SettingsList -> settings helpers -> catalog/candidate endpoints.

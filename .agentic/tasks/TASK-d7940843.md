## Design

Approach: REQ-FUNC-ff5743b4 uses existing post-build stamping to record hashes; release checker compares current inputs and generated files, then independently rebuilds in temporary storage to detect restamping stale output. Commit production assets with every build-input change. Packaging already invokes the checker before building.

Interfaces and data: deterministic JSON stamp lists relative paths and SHA-256; missing, invalid or mismatching data fails the release check and directs a rebuild. The checker also requires Node and locally installed Vite for a fresh comparison. Text inputs are normalized to LF for Git checkout portability.

Files and test seams: stamp_web_assets.py and check_release_consistency.py; isolated temporary-copy probes cover matching, stale input and tampered output without automated setup/deployment tests.

Risks and open decisions: build output must be deterministic for a given pinned dependency set; source changes after stamping require rebuild. No data migrations or runtime service changes.

Requirement map: REQ-FUNC-ff5743b4 maps to post-build stamp and release check.

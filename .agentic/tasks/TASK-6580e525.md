## Design

### Approach
OBSERVED: existing supervisor/admission and durable configuration ownership remain authoritative.
Add read-only scoped capacity and operation projections in web/app.py and WebStore; reuse the supervisor's occupied-slot semantics (REQ-FUNC-42643886).
Use a compact ProjectCapacity component on Summary/Jobs and a server-backed recent-operation panel across project tabs; no second client queue or operational setting (REQ-UX-5243a55c).
System status lists roles; readiness names failed server components and leaves missing project workers local (REQ-REL-329421d1).
### Interfaces and data
Capacity includes project identity, canonical limit/default 1, occupied/free, queued jobs and pending request reasons; staged settings are separately identified, never counted as executing jobs.
Heartbeat freshness and observed idle/busy remain independent of capacity. Public status excludes PIDs/owner capabilities.
Persist only editable, non-secret draft strings/base revision in per-account/project sessionStorage, validated and bounded; explicit discard clears them, stale revisions block save (REQ-UX-0f6e2c63).
Durable operations already live server-side; project status restores the latest own execution/control/configuration outcome after reload without resubmitting.
Reduction below occupancy returns capacity_below_occupancy and keeps the staged candidate; a shared core admission_limit reader immediately applies min(active N, current staged N) across conductor/supervisor/status while preserving exact active bytes for admitted jobs; existing safe apply rules otherwise remain (REQ-FUNC-ed8e4793).
### Files and test seams
adore/capacity.py shared staged-lower-ceiling reader, orchestrator/supervisor integration; web/app.py, web/store.py and new web/status.py projection; frontend App.tsx, ProjectCapacity.tsx, projectStatus.ts, settingsDrafts.ts; targeted HTTP tests and one bounded browser file.
Four-locale copy, settings help and existing help topics; Web interface/Worker/Configuration component docs, knowledge and context, changelog/release notes; rebuild static bundle.
The latest user clarification distinguishes pending reservations from already-started execution: supervisor child dispatch is capped without an initial-reservation bypass; initial_start_slots plus an atomic admission boundary defer conduct_run without consuming its dispatch until actual started slots fall below effective N (REQ-FUNC-3b737a5c).
### Risks and open decisions
No stored format migration or legacy reader. Drafts must not retain secrets/full config or cross accounts. Corrupt projections fail closed without blocking unrelated project reads.
No live acceptance or full suites: targeted offline proof per explicit user instruction, final integration deferred.

## Design

### Approach
OBSERVED: project-global locking currently encloses remote calls and execution. Use a short admission transaction for local uniqueness/capacity only; serialize lifecycle and journals with crash-released OS run locks. Keep synchronous poll compatibility while exposing admission-only and owned-run conduction for the supervisor.
### Interfaces and data
REQ-FUNC-58a8d9d5: poll_once selects/probes outside admission then rechecks eligibility, pause and capacity locally before durable reservation. No external effects while holding admission.
REQ-REL-ab1c7560 / REQ-REL-4659ba9d: reconciliation takes one nonblocking run lock and claims WK-01 run_scope before effects; durable foreign ownership skips all mutations, including cancel and outbox replay. Standalone OS locks retain safety without web dependencies. Lock order is run then short admission; no admission section waits for a run lock.
REQ-FUNC-cbac7e6c: conduct_run(run_id, config_revision) uses a fresh CLI engine, exact revision and worker-owned target. Admission reserves a kernel execution slot, releases the short lock, then initializes and saves the pinned worktree/workflow before acknowledgement. Closed atomic dispatch evidence grants one initial launch. Unknown publication stays failed for explicit recovery.
REQ-FUNC-eb167b66: Retry and all automatic resumptions reserve working lifecycle under admission before execution. A reduced limit blocks further reservations only. Parked cleanup and handoff-pending retain occupied slots until settled; idle approval/review do not use executor slots.
REQ-DATA-4f49d9f6: required current-state execution_pending freezes all queued reads/saves; clock activation is saved before dispatch consumption/effects, excluding waiting before first executor work; inactive-state clock logic continues to preserve prior work on resume.
### Files and test seams
StateStore scoped OS locks, orchestrator admission/conduction/reconciliation, CLI single-run dispatch and WorkerContext durable owner checks; public fake-engine and independent-store tests. Update component docs, CLI/operator guide, localized help and release notes.
### Risks and open decisions
No data migrations or legacy readers; no target-repository retesting. Kernel locks release on process death and remain conservative on I/O failure. WK-01 durable owner evidence supplements locks across dispatch gaps. Supervisor process scheduling belongs to the next ticket. Targeted-only proof is the user's explicit decision.
### Requirement map
All six requirement IDs map to the decisions above and tests/test_run_concurrency.py; CLI tests cover transport/ownership boundaries.

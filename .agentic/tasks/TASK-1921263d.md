## Design

### Approach
REQ-FUNC-43e2f999: add Supervisor and ProjectWorker event loops in web/supervisor.py.
The production entry and portable service route to Supervisor; CommandWorker remains the
bounded synchronous command/result processor reused in isolated command children.
Supervisor discovers stable IDs and never waits for jobs in its loop. A separate
configuration process consumes existing pause/resume/delete commands independently;
#88 extends that consumer with actual configuration work.
ProjectWorker starts bounded admission children with --admit-only, and one revision-bound
conduct child per eligible run, up to N. Canonical atomic admission governs all Start,
Retry and reconciliation paths. Poll/backoff/quiet windows and scheduling are local.

### Interfaces and data
REQ-REL-c240007b: ProcessTree launches a gated wrapper before effects. Windows uses
kill-on-close Jobs, Linux owned process sessions; strict ancestor PID/birth transport
is checked before effects, and a wrapper watchdog stops children on parent loss.
Web schema 18 adds the command role; other schemas stay unchanged. Existing ownership/dispatch records remain authoritative.
Transient command owners are independent of the scheduler; watcher-claimed cancels
are drained before command exit, with dead remainder claims uncertain. A drainer
retains at most 64 KiB of process output. Linux cleans exited wrapper groups while waitid keeps the leader unreaped; no
recycled group ID is signalled. Shutdown attempts every scope despite a failure;
supervisor cleanup refusal quarantines only that project.
REQ-REL-af360022: stop all children first, then one shared grace deadline and forced
tree termination; preserve running/uncertain evidence and recover only proven dead scopes.
REQ-FUNC-e93e4944: look up names afresh from project_id, including queued requests;
archive/delete terminates that worker. Rename restarts only that project's worker so
loaded config paths cannot follow a reused name. Never replay consumed working/publishing.

### Files and test seams
Add processes.py and supervisor.py plus targeted test_web_supervisor.py. Update commands.py
filtering/entry, WorkerContext ancestry checks, portable launch.py and service/user/component
notes. Inject process factories and clocks for scheduling failures; spawn offline Python
helpers for actual overlap and parent/child death. No deployment script tests.

### Risks and open decisions
Keep unknown process evidence fail-closed. An uncertain external operation retains its
record and requires explicit recovery; process death is not evidence of remote outcome.
Only targeted proofs per explicit user instruction; global proof deferred to umbrella.

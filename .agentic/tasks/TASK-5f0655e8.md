## Design

- D1 `GET /api/v1/executor-images?runtime=docker|podman` (administrator): runs `<runtime> images --format {{.Repository}}:{{.Tag}}` through the injectable probe runner with a timeout; returns `{runtime, available, images[]}` sorted and unique, without `<none>` entries; an unknown runtime is 422; a failed or missing runtime gives `available: false, images: []`.
- D2 `ProjectInput`: credential names may be empty in API-key mode (the executor then gets no forwarded variables, as the DCP Pi projects); all other environment validation unchanged.
- D3 EnrollmentWizard step 2 fields: executor, model, Runs in (`execution_backend`: Container / Installed on the server), then for container Runtime (docker/podman select) and Image (text input with a datalist from D1 and a "not on this server" hint when the list is available and lacks the value; when the current value is the old default and a `<repo>:<executor>-*` image exists, it is proposed), for local the native command and local account fields with the existing local notice; credentials last, names optional.
- D4 Settings: `_external_environment_key` no longer covers `execution.backend`, `container.runtime`, `container.image`, `local.account`, `local.home`, `local.path`, `local.cgroup_root` (an allow-list `_CHOSEN_ENVIRONMENT_KEYS`); everything else stays external. They are editable through pending review (direct PUT keeps requiring review for execution./local.), shown in Agent and model (`settingVisible` executor tab) with the runtime as validated text (docker, podman or `wsl ... -- docker|podman`, amended in review round 1) and image suggestions; ExecutorEnvironment copy no longer says the environment is chosen outside the web.

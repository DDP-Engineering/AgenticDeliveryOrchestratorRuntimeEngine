Desired outcome: STATED automatically discover installed OpenCode/Pi/Codex/Qwen and prefill native argv, with manual executable selection on Windows/Linux, then rebuild and test both portable packages.
Actors: Administrator using enrollment and Agent and model Settings on the ADORE host.

## Design

REQ-FUNC-cd5bffc3: Add a standard-library executor discovery module with injectable system/environment/home and bounded filesystem scans. Return a closed schema with actual host/account and each supported agent's native launch choices. Resolve executable identities and use supported command presets; detect known npm native layouts or Node+JS entrypoints without reading credentials or executing discovered files. Ignore relative search roots, unsafe shell entrypoints and paths under cwd/repository; deduplicate canonical paths. Admin-only GET /api/v1/local-executors returns host suggestions, no mutation. Existing local policy revalidates files on actual use.
REQ-UX-3ce12a1a: Shared React component fetches current-host suggestions only in local mode. First available command is proposed only into an empty/default/previous automatic command. Agent switches replace previous auto proposals; typed full commands remain owned by the user. Installed selector and explicit absolute executable path replace the executable while preserving standard arguments; Node entries include JS path. A text path is used because a browser file picker returns uploads rather than server paths. Saved Settings commands are preserved until the administrator explicitly chooses an installation. Failed/malformed/stale reads never erase manual input. Local options identify host/account; Linux-only cgroup field hidden on Windows when host system is known.
State: Discovery has no durable state or installs; current candidate/revision/CSRF/write guards remain unchanged. No database or config migration. Container behavior unchanged. Four locale strings and help describe actual behavior.
Alternatives: Parsing arbitrary .cmd/.ps1 shims rejected because wrappers are executable input; known package layout plus actual native paths is narrower. Invoking CLIs for versions rejected because discovery must not start executable code or model providers.
Architecture: Enrollment/Settings -> shared local picker -> admin discovery GET -> bounded host filesystem -> launch candidates; existing reviewed configuration -> existing local_policy -> native scopes.
Expected changes: new executor_discovery.py and tests; web/app.py; shared frontend helper/picker and enrollment/editor integration; UI tests, user/component docs, knowledge, help and release notes. Packaging scripts only as required for acceptance evidence; outputs stay in 07_Delivery.
Risks: Installation layout differences use manual fallback; settings changes preserve saved custom commands; scan count and path length capped. No unresolved design decision.

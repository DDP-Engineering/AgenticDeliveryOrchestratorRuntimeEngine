## Frame

Problem: the Tickets table lists every open ticket (up to 500 per read) on one page, so users scroll a long way when a repository has many tickets. STATED: "la tickets pentru ca pot fi multe, acel tabel ar trebui sa aibe numar de pagini si selector cate randuri se afiseaza. Pentru ca altfel, user-ul ar trebui sa scrolleze destul de mult cand sunt foarte multe tichete." (screenshot of the project Tickets sub-tab).
Desired outcome: the Tickets table shows 10 rows per page by default with a Rows per page selector (10, 25, 50, All), the visible range, the page number of the page count, and Previous/Next, like the Jobs table pager.
Actors: administrators and developers using a project's Tickets sub-tab (and the multi-project ticket view, which uses the same component).
Primary scenario: Read tickets -> 53 tickets -> page 1 of 6 shows #53..#44 -> Next -> page 2 of 6 -> 25 rows per page -> page 1 of 3.
Examples: 7 tickets -> no pager (same threshold as other tables: more than 10 rows).
Counterexamples: no server paging (tickets are read once, up to 500); an open Details row stays with its ticket.
In scope: 04_Software/web/src/TicketWorkspace.tsx, ticketCopy.ts (page label, four locales), e2e tickets.spec.ts, help tickets topic (four locales), CHANGELOG, release note, requirement.
Out of scope: sorting or filtering tickets; changing the 500-ticket read limit; full suite (STATED earlier: at the end).
Constraints: reuse the existing table-pagination pattern and i18n keys rowsPerPage/previous/next/all.
Success signals: e2e shows pages and the selector; existing ticket tests stay green.
Evidence: OBSERVED TicketWorkspace renders all rows; tickets.py reads up to TICKET_LIMIT=500 in one request; JobWorkspace/ObservedTimeline use .table-pagination with 10/25/50/All, range and Previous/Next.
Assumptions: none. Unknowns: none.
Decision-blocking questions: none.
Proposed behaviors: B1 client-side pagination of the Tickets table (REQ-UX-06b1d542).
Path and reason: quick - one component, an established pattern, no API or contract change.

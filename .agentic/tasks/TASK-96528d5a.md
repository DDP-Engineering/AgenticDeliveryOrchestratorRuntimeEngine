## Design

### Approach
REQ-NFR-d2310ebf: existing-store audit and historical owner validation run outside writer transactions. Fresh initialization is atomic, and owner registration rechecks the indexed latest-generation snapshot under a short write transaction.
REQ-REL-321e1493: SQLite short BEGIN IMMEDIATE claims bind a closed domain, immutable project/run target, owner ID and monotonic scoped generation. Execution and project/global configuration cannot consume one another. Existing pause/resume/delete are configuration-project operations; settings application retains existing reviewed protected references.
REQ-REL-b5daa269: durable owner records identify role, project, run, host, PID and process birth. Heartbeat is observational, never a lease expiry. Recovery inspects processes outside the write transaction, then CAS-rechecks the exact owner before invalidation. Unknown liveness retains ownership. Child CLI participation prevents parent death stealing an active engine.
REQ-SEC-f985d1ea: every completion, effect authorization and heartbeat checks active owner/generation. Graceful shutdown refuses to relinquish in-flight effects. The worker rechecks immediately before runner/cancel signal; child CLI carries the bound operation and checks before admission/publication/state effects.
REQ-SEC-20016f19: claim checks account/grants and immutable profile, then worker repeats before effects; stale requests become failed with closed reason codes. Profile filesystem reads occur outside SQLite writer transactions and identity is rechecked at effect boundaries.
REQ-FUNC-d5bf9373: an admission callback after durable picked evidence confirms Start before conduct; later job failures cannot rewrite admission success.
REQ-FUNC-c6dd1096: Cancel keeps its operation running after signal and requires saved cancelled lifecycle to acknowledge success.

### Interfaces and data
Actual conductor/publication run scopes acquire unique run-role owners and child heartbeats; run-role commands restrict reconciliation to their exact run while capacity remains project-wide; Start saves the exact run owner with admission. Web database gets one new current schema; older stores are refused with deletion guidance, without migration. Owner records have explicit supervisor, project, run and configuration roles, durable process participants and active/stopped/dead states. Tokens are generated server-side and omitted from public operation projections. No credential material or arbitrary configuration payload is queued.
WebStore registration/heartbeat/claim/assert/finish/recover/release methods use explicit owner handles; scoped execution/configuration requests remain idempotent per actor/key. A configuration reference has an explicit project or explicit global scope, never a default project. A lost owner raises typed OwnershipError; unconfirmed effects stay uncertain and are not replayed.

### Files and test seams
adore/web/store.py and ownership.py: durable schema and ownership, deterministic injectable process identity/liveness. adore/web/commands.py: scoped claims, child context, cancellation reconciliation and heartbeat. adore/cli.py and orchestrator.py: admission callback and child fencing. New tests/test_web_ownership.py uses barriers/events and independent stores; existing command/audit/server/engine tests are updated for explicit claims. Component/user docs, release notes and relevant four-locale help describe admission/cancellation.

### Risks and open decisions
No multi-host takeover, no heartbeat-based theft, no migration, no branch/version changes. External side effects are not exactly once: unknown outcomes remain uncertain. Process identity failures retain ownership. Later tickets own process-per-run topology and independent configuration scheduling; this ticket supplies and integrates their durable contracts.

## Frame

Problem: From the project hub, Jobs and Statistics jump to separate pages with a different header ("Project context" band + Job scope selector), a visible layout transition and duplicated project information (STATED: "se face o trecere vizuală"; "avem job scope - avem project (care e același lucru)").
Desired outcome: Jobs and Statistics are hub tabs with the same structure as Summary/Settings; global Overview/Jobs/Statistics pages show the project only through their own selector (STATED: user chose "Jobs și Statistics" and "Scot banda").
Actors: administrator and developer viewing an authorized project; browser history/deep links.
Primary scenario: user in project hub clicks Jobs -> hub stays, Jobs tab selected, start-job form + filters + table shown -> click a job -> detail opens in the same tab, URL /projects/<id>/jobs?run=<run>.
Examples: aegis hub > Jobs shows ticket form and empty job list without a "Job scope" panel; aegis hub > Statistics shows period + statistics tabs without a Project selector.
Counterexamples: global Jobs page from the side menu keeps its project selector (no separate Project context band); /jobs?project=<id> and /metrics?project=<id> still work.
In scope: hub tabs Jobs/Statistics (both roles), in-tab job detail (also from Summary/History), fixed-scope JobWorkspace without scope panel, project statistics without selector, routes for /projects/<id>/jobs[?run] and /projects/<id>/statistics[?tab&period], removing the Project context band from global pages, tests/docs/requirements.
Out of scope: backend/API; global page features; full suite (STATED: run at the end of refinements).
Constraints: preserve authorization fallbacks and existing global deep links (OBSERVED routes.ts normalizeRoute; e2e shell/jobs/statistics specs); four locales unchanged.
Success signals: hub shows six/five tabs per role with no links; Jobs/Statistics content renders under the hub; no Project context band outside the hub; focused unit/e2e green; DCP shows it.
Evidence: OBSERVED App.tsx:960-973 projectContext band + hub links; App.tsx:936-939 workspaceProps.onOpen switches to page jobs; JobWorkspace.tsx:248 scope panel (select hidden by fixedScope, note+worker kept); App.tsx:410/446 metrics loads gated by page === "metrics"; App.tsx:1083-1163 metrics block; REQ-UX-78923e00 still listed Prices (stale from TASK-eb139031) - fixed here.
Assumptions: History tab benefits from the same fixed-scope simplification; statistics "projects" sub-tab remains global-only.
Unknowns: none blocking. Decision-blocking questions: resolved (scope: Jobs+Statistics; remove band on global pages).
Proposed behaviors: B1 Jobs tab (REQ-UX-b309b302); B2 Statistics tab (REQ-UX-b77fdd9e); B3 hub tab set/order (REQ-UX-d88d3d7f, REQ-UX-78923e00, spec b758d2b7); B4 identity band only in hub (REQ-UX-0713852d, REQ-UX-b5485c02); B5 URLs (spec REQ-UX-4200375b).

## Design

- D1 routes.ts (REQ-UX-b309b302, REQ-UX-b77fdd9e, REQ-UX-4200375b): ProjectTab adds "jobs" | "statistics"; projectDetails route gains optional `run` (jobs tab only, identifier alphabet) and `metricsTab`/`reporting` (statistics tab only, same validation as /metrics; "projects" sub-tab rejected). parse/format round-trip; other tabs ignore these queries.
- D2 App.tsx hub (REQ-UX-b309b302, REQ-UX-d88d3d7f): projectTabs = [overview, configuration, (access), jobs, statistics, history]; hub RouteLinks removed; labels jobs/metrics copy. Jobs panel = JobWorkspace mode="jobs" scope={selected} run={requestedRun} fixedScope. `hubWorkspace.onOpen` sets requestedRun + projectTab "jobs" (no page change) and is used by Summary, Jobs and History. currentRoute/applyRoute carry run, metricsTab and reporting for those tabs.
- D2b JobWorkspace.tsx: when fixedScope, the scope panel is replaced by the compact worker alert used by Overview (only unavailable/error).
- D3 statistics (REQ-UX-b77fdd9e): the metrics block becomes one render function `statisticsView(fixed)`; page metrics renders it unfixed, Statistics tab fixed (no project select, no All projects option). Loads gated by `statisticsVisible = page === "metrics" || page === "projectDetails" && projectTab === "statistics"`; `allProjectScope` only on page metrics. Sub-tab list excludes "projects" when fixed.
- D4 band (REQ-UX-0713852d, REQ-UX-b5485c02): projectContext renders only for page projectDetails; the all-project statistics scope note stays.
- Compatibility: /jobs?project and /metrics?project remain global views. No backend change. Test seams: tests/routes.test.mjs (D1); e2e jobs.spec hub test + new hub jobs/statistics test (D2/D3); shell.spec and jobs.spec context assertions updated (D4).
- Expected files: web/src/{App.tsx,JobWorkspace.tsx,routes.ts}, web/tests/routes.test.mjs, web/e2e/{jobs,shell}.spec.ts, docs. Risks: large inline App.tsx block move; mitigated by focused e2e (jobs, shell, statistics specs).

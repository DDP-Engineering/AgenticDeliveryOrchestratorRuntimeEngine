Desired outcome: Background command output remains captured without user interaction.
Actors: ADORE runner, worker, native executor, container target, Windows/Linux service account.
Primary scenario: automatic launch -> child-only pager environment and Windows no-window flag -> captured output.

## Design

REQ-PLAT-989c6478: util owns a pure child-environment copy with forced GIT_PAGER=cat/PAGER=cat, case-insensitive removal of conflicting names, and explicit-env isolation. Apply after native account/profile/key selection and at process-controller entry; container exec adds the values inline after caller values, preserving secret forwarding and WSL behavior.
REQ-PLAT-967d0c80: util owns Windows subprocess options using CREATE_NO_WINDOW. Use for shared run_command, worker, native supervisor and regex probe. The isolated standalone local_child duplicates the single Windows flag because Python -I intentionally excludes package imports; its environment comes from the trusted parent. No shell, detached/breakaway process, global environment mutation, or changes to PID/Job/cgroup receipts.
Container model/preparation runners inherit the forced exec environment and run in Linux, so their launch code needs no Windows change.
Inputs/outputs, durable schemas, failures and retry behavior remain stable. Keep stdin closed on background host runners; regex probe retains its JSON stdin input. No migration.
Expected files: seven product modules, focused runner/native/isolation/worker/config tests; component/operator docs, knowledge/context, changelog and four-locale release note. No UI/settings changes; help: none because no described screen or workflow changes.
Test seams: mocked subprocess/owned native spawn/container CLI runners; current timeout, OS failure, stream capture and ownership negative regressions. No live forge/model/container execution.
Alternatives: global Git config rejected because manual sessions must retain their settings; prepending --no-pager alone rejected because Git commands issued by executor tools also need inherited defaults.
Risks: Explicitly detached GUI commands can ignore launch defaults; already running processes cannot inherit future changes. Architecture structure unchanged.

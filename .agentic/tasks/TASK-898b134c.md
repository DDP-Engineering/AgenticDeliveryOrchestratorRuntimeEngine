## Frame

Problem: every Pi run gets the egress the operator set in `[container.egress]
mode` (default `open`), and Pi has no web tools: pi-web-access is installed in
the image but never loaded (OBSERVED `adore/config.py` ContainerEgressConfig
mode="open", `adore/executor/launcher.py` pi_rpc_argv loads only the guard,
`docker/Dockerfile.executor-base` installs pi-web-access@0.46.0). `[executor]
internet` and `[executor.web]` are refused as unknown keys (OBSERVED PI-04 hand-over).
Desired outcome: one project setting, "Internet access for the agent", decides
what the agent reaches. Off: only the model provider. On: the open internet, so
the agent can search the web, read pages and download libraries (STATED ticket
#56 Goal). Default Off (STATED PLAN 11.1).
Actors: administrator (Settings -> Agent and model), developer (read-only), the
conductor launching Pi per stage, Test AI connection, the readiness check,
server-installed (local backend) projects.
Primary scenario: a container project keeps the default Off; each stage runs on
the per-run allowlist proxy that admits only the provider's hosts, Pi answers,
`curl https://example.com` is refused, and Pi has no web tools and is told
internet access is off. The admin switches it On (warned that a malicious page
could try to make the agent send its key or ChatGPT token out); the next stage
runs with open egress and pi-web-access (Exa, no key) loaded: `web_search`,
`fetch_content`, `npm install`, `pip install` work (STATED ticket Decisions/AC).
Examples: provider `custom` with base_url `http://192.168.1.20:1234/v1` -> Off
allowlist `192.168.1.20`; provider `chatgpt` -> `api.openai.com` (OBSERVED pi-ai
`auth/oauth/openai-chatgpt.js` API base `https://api.openai.com/v1`, fixtures
`run_tool_calls_chatgpt.jsonl` baseUrl api.openai.com; the token refresh runs
in PI-05's helper container on the default network); provider `anthropic` ->
`api.anthropic.com` (OBSERVED pi-ai `providers/data/anthropic.json` baseUrl).
`[executor.web] search = "brave"` with internet On -> Pi gets `BRAVE_API_KEY`
from the credential store and web-search.json names brave (STATED ticket Decisions).
Counterexamples: Off never loads pi-web-access (STATED SPIKE Plan changes 5);
no download tool is added (STATED Decisions); the ChatGPT helper container keeps
the default network (STATED PI-05 hand-over).

## Design

**Approach.** `[executor] internet` is the only user knob; ADORE derives the
run's egress from it (REQ-SEC-e2ca6d05, REQ-FUNC-f801e9f3) with a new
`config.egress_policy(config) -> EgressPolicy` (mode, allowlist, no_proxy,
proxy image/port, network prefix) that ContainerManager consumes in place of
the TOML section: Off = `allowlist-proxy` with `pi_providers.provider_hosts()`
plus `[container.egress] allowlist`; On = `open`. The three ContainerManager
construction sites (orchestrator, web readiness, model_connection) call it, and
the enrollment/import reviews show the derived mode. `[container.egress]` keeps
allowlist (extra hosts while Off), no_proxy, proxy_image, proxy_port,
network_prefix; `mode` is refused by name (REQ-FUNC-f5e692dc). Rejected: keeping
`mode` beside the switch (two sources of truth; the ticket says the user sees
only the switch).
Hosts (REQ-FUNC-4ebeb792): the catalog generator reads every `baseUrl` of
`pi-ai/dist/providers/data/<id>.json` into `hosts`; chatgpt uses the openai
hosts (Pi provider openai, API base api.openai.com; refresh stays in PI-05's
helper container); custom uses the endpoint URL's host.
Web tools (REQ-FUNC-f1b71231, REQ-FUNC-53fd0c28): PiExecutor gets
`internet`/`web_search`; On and search != none -> `-e <pi-web-access>` and
web-search.json `{provider, workflow:"none", toolActivation:"eager"}` copied
into the agent directory the way models.json is (shared `_place_file`, failure
-> REQ-FUNC-95778891); Off -> `--append-system-prompt <notice>` and nothing
loaded. Keys never enter the file: pi-web-access reads BRAVE_API_KEY /
TAVILY_API_KEY from the environment (REQ-SEC-b6a4a434 via secret_names, which
also feeds the credential variables list).
Proxy (REQ-SEC-19b768d6, REQ-FUNC-67d99144): squid.conf gets `dstdomain` for
names and `dst` for IP literals; the proxy container gets the `--add-host`
options of run_args.

**Interfaces and data.** Config keys `[executor] internet` (bool, false),
`[executor.web] search` (exa|brave|tavily|none, exa). Catalog provider entries
gain `hosts` (1-8 host names). Readiness record gains optional checks
`egress_proxy`, `web_search_key` (REQ-FUNC-aaa37a72). Settings rows
`executor.internet` (boolean, On/Off labels) and `executor.web.search` (choice)
through the generic reviewed edit (REQ-UX-e340fc1e).

**Files and test seams.** config.py, pi_providers.py, pi_catalog.json,
02_Tools/generate_pi_catalog.py, isolation.py, executor/launcher.py,
branding.py, orchestrator.py, web/app.py, web/model_connection.py,
web/executor_settings.py; web/src App.tsx, executorSettings.ts, settingHelp.ts,
settingKeys.json, settingsCopy.ts, readiness.ts, ReadinessEvidence.tsx,
EnrollmentWizard.tsx; tests test_config, test_pi_providers, test_isolation,
test_pi_rpc/test_executor_launcher, test_orchestrator, test_model_connection,
test_web_* readiness, web unit tests, e2e/settings.spec.ts.

**Risks and open decisions.** Default Off means a container project now needs
the egress proxy image (readiness reports it) and dependency downloads fail
until #26 or an allowlist entry; this is the owner's default. A server-installed
run is not restricted (UI note). With On, a page can try to exfiltrate the key
or ChatGPT token (UI warning). Removing `mode` is a breaking config change: one
CHANGELOG line names the key to delete.

**Requirement map.** REQ-FUNC-06b861ec/77b798cf/f5e692dc -> config.py;
REQ-SEC-e2ca6d05, REQ-FUNC-f801e9f3 -> egress_policy + call sites;

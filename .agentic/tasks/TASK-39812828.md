## Frame

Problem: Project configuration lives under Administration/Settings, so developers cannot inspect it while viewing project details.
Desired outcome: A project's settings appear on its detail page with understandable type, domain, and purpose guidance.
Actors: Assigned developer (read only); platform administrator (read and edit).
Primary scenario: Open project details, expand Settings, inspect effective values and guidance; an administrator stages a change there.
Examples: A developer sees their project's container image and polling interval; an administrator selects the runtime from permitted values.
Counterexamples: A developer cannot view another project or submit a config change; secret values remain redacted.
In scope: Scoped configuration read API, Project details configuration presentation and admin edit controls, four locales, documentation and deployment.
Out of scope: Changing configuration persistence and administrator approval/apply gates; project removal decision remains in TASK-48ddbb7d.
Constraints: Existing redaction and RBAC, responsive layout, DCP real project data and secrets preserved.
Success signals: Assigned developer can read only their redacted project configuration in details; administrator can stage/apply there; field help conveys type and permitted values.
Evidence: STATED by user; OBSERVED in `App.tsx`, `app.py`, `test_web_config.py`.
Assumptions: "see them (as developer)" grants read access only. Settings means project config, endpoint and estimates; account preferences remain under Administration/Settings.
Unknowns: None blocking.
Decision-blocking questions: None.
Proposed behaviors: Reuse current redacted config response and staged admin mutation endpoints; render typed values and help near project details.
Path and reason: Full path because developer read access changes an authorization boundary. Autopilot follows the user's standing preference for minimal interruptions and this explicit implement/deploy request.

## Design

Reuse the existing validated and redacted config response, changing only its read dependency from administrator to authenticated project membership. Keep all mutation routes and the staged candidate flow administrator-only. Move project-specific forms out of Administration/Settings into Project details. Render effective values in collapsible configuration sections; common fields share localized purpose/domain metadata with the admin editor, which uses enum selects and positive integer input constraints. Bind loaded configuration, pending candidate and prices to the immutable selected profile ID so async responses cannot display under another project.

## Design

REQ-FUNC-cacfa8b2: New gitea_auth.py owns metadata-only strict login parsing, standard root enumeration and portable_tea_runner. First execute the requested command unchanged; recover only exact no-logins/named-login-missing CLI errors with no HTTP result. Metadata uses bounded tea logins JSON; current CLI view wins, explicit XDG forbids fallback; otherwise inspect standard absolute account roots for tea/config.yml without reading credentials. Explicit login wins, then one default, then sole login; ambiguity/corruption fails closed. Retry the same API operation once with --login and a copied environment. Do not retry HTTP failures or scoped credentials.
RepositoryAuth project_runner uses protected credentials first; only absent Gitea records enable external discovery. Other providers/commands pass through. CLI engine already consumes project_runner. Web new/transfer probes wrap raw runner; saved-project probes opt out of extra wrapping because project_runner already owns authority. Readiness catches closed auth errors as an ordinary failed forge_auth check. Ticket API maps closed errors; enrollment suggestions reuse the same metadata source.
REQ-UX-163a1c99: Add safe localized errors, readiness remedy and dialog instructions: Project Summary -> Connect repository -> Repository server + Access token -> Verify and connect -> Check host prerequisites. Explain credentials belong to the actual ADORE account/machine and Git transport remains separate. Update four-locale projects/help content, operator/component docs and notes.
No durable schema/config field, credential relocation, process-global environment mutation or new dependency. Existing successful runner behavior and scoped failures remain unchanged.
Test seams: public discovery/wrapper, project_runner/scoped precedence, API ticket/setup errors, pure localized error helpers and help structure. No live CLI/network/model/job checks.
Risks: Explicitly isolated app stores remain inaccessible and require Connect repository; detection proves login metadata only until the retried forge request validates HTTP. No architecture split beyond the new auth-policy helper.
Expected product paths: doctor.py, gitea_auth.py, repository_auth.py, web/repository_source.py, web/app.py, errors.ts, ReadinessEvidence.tsx, RepositoryConnection.tsx, localized help, notes; corresponding tests/docs/context.

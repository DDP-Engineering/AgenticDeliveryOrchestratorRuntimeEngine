## Frame

Problem: Estimated token prices are edited on a separate admin-only Prices tab, away from the executor and model they price (STATED: "setare de preț ține de executor și model, care sunt acolo selectate").
Desired outcome: Administrators set and review estimated prices inside Settings > Agent and model, next to the selected executor and model; the Prices tab no longer exists (STATED: "Mută setarea de preț în Agent and Model").
Actors: administrator (edits prices); developer (sees Settings read-only, no prices); browser holding an old /projects/<id>/prices URL.
Primary scenario: admin opens project > Settings > Agent and model -> the group shows the estimated-price form, prefilled with the project's executor and its configured model, and the price table -> saving adds the row to the table.
Examples: aegis uses executor pi with model X -> form shows executor pi, model X; admin edits rates and saves -> table lists the new row.
Counterexamples: developer opening Settings sees no price form; /projects/<id>/prices no longer shows a Prices tab.
In scope: move form + table into the Agent and model group; remove the Prices tab; prefill model; legacy /prices URL opens Settings; update affected tests, requirements, route spec and web-interface knowledge.
Out of scope: price API/storage/validation (04_Software/adore/web/app.py, store.py unchanged); cost calculation; full test suite (STATED: run at the end of all refinements).
Constraints: preserve admin-only price editing (OBSERVED App.tsx:211, :1069); keep four locales (OBSERVED src/i18n.ts); deploy to DCP for user testing (STATED).
Success signals: hub shows Summary, Settings, Access, Jobs, Statistics, History for admins; price form + table visible inside Agent and model; /prices redirects to Settings; focused unit + e2e tests green; live DCP shows the new placement.
Evidence: STATED quotes above; OBSERVED App.tsx:211 tab list, App.tsx:1069-1074 price panel, App.tsx:1423/1464 executor group slots, routes.ts:25-26 + :92 legacy executor redirect, tests/routes.test.mjs:34,74, e2e/jobs.spec.ts:106; INFERRED the executor slot executorAfter is the natural host.
Assumptions: executor and model fields stay editable (prefilled, not locked) so prices for other models can be recorded before switching; the price table keeps listing all project prices.
Unknowns: none blocking.
Decision-blocking questions: none.
Proposed behaviors: B1 price form + table inside Agent and model for admins only; B2 form prefills executor and configured model, resetting per project; B3 project hub has no Prices tab; B4 legacy /prices URL normalizes to Settings for both roles.
Path and reason: full - observable behavior of REQ-UX-d88d3d7f, REQ-UX-d93fab0f and the REQ-UX-4200375b route table changes.

## Design

- D1 (REQ-UX-90ffe980): move the price section from the `prices` tab panel (App.tsx:1069-1074) into the `executorAfter` slot of `SettingsList` (rendered at the end of the `executor` group, App.tsx:1464), guarded by `isAdmin && selected`. Heading becomes h3 inside the group; class `executor-prices` mirrors `.executor-endpoint` spacing. `savePrice`, `prices` state and the price API stay as they are.
- D2 (REQ-UX-d93fab0f): the form keeps `key={selected}`; executor default = project executor (existing rule); model `defaultValue` = applied `executor.commands.<executor>.model` from `projectConfig.config` via `settingValue`. Fields stay editable (Frame assumption). `form.reset()` after save returns to these defaults.
- D3 (REQ-UX-d88d3d7f, REQ-UX-4200375b): drop `prices` from App.tsx project tabs and from `PROJECT_TABS`/`ADMIN_PROJECT_TABS` formatting use; keep `prices` in the `ProjectTab` parse set so `normalizeRoute` maps it to `configuration` with `replaced: true` for both roles, alongside the legacy `executor` redirect (routes.ts:92).
- Compatibility: bookmarks to /prices land on Settings. No backend, data, or migration change; rollback = redeploy previous static bundle.
- Test seams: tests/routes.test.mjs (B4, plus table/loop updates in routes/jobs tests); e2e/executor-config.spec.ts new test (B1, B2); e2e/jobs.spec.ts:106 hub list (B3).
- Expected files: web/src/App.tsx, web/src/routes.ts, web/src/styles.css, web/tests/routes.test.mjs, web/tests/jobs.test.mjs, web/e2e/executor-config.spec.ts, web/e2e/jobs.spec.ts, .agentic knowledge/requirements/spec.
- Alternatives: locking executor/model to the active selection was rejected because prices for a model are useful before switching to it. Risks: none beyond layout; the existing `executor` group must exist (it always lists executor rows). No architecture drawing owed (behavior-only).

## Design

### Approach
REQ-UX-9372e8ae: reuse a password field with accessible independent toggles in both own-password forms. REQ-UX-fc2abe3a: retain the existing eight-character guidance. REQ-FUNC-aa763f56: require repeated password and validate equality before submitting.

### Interfaces and data
Password fields stay masked by default; local confirmation is never sent. Preserve the API body, reset behavior and server policy. Localized mismatch is visible and correctable.

### Files and test seams
App.tsx, i18n, styles and offline browser tests; update operator/component/help documentation, release notes and bundle.

### Risks and open decisions
Passwords remain transient in the form; no logging or storage. Inputs retain autocomplete semantics.

### Requirement map
REQ-UX-9372e8ae and REQ-UX-fc2abe3a map to common fields; REQ-FUNC-aa763f56 maps to the shared submit handler, tested through both public flows.

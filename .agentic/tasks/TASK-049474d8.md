## Frame

Problem: Statistics needs scrolling: the reporting period spans several rows with a time zone selector, a misaligned All time button and two explanatory paragraphs, and the Summary repeats the active-job count already shown on project Summary/Overview (STATED: "Șterge timezone, aliniază butonul All Time, redu din text"; "Current state - nu e duplicat?"; "reporting period trebuie să fie gen one line").
Desired outcome: one compact reporting-period row; no time zone control, no boundary/legend text, no Current state panel.
Actors: administrators and developers viewing project or global statistics.
Primary scenario: open Statistics -> one row: Reporting period | (Project) | From | Through | Group by | All time | Export CSV -> statistics cards follow without the current-state panel.
Examples: aegis hub Statistics; global /metrics with project selector.
Counterexamples: reporting still UTC by default; an old link with ?timezone=Europe/Bucharest still applies that zone; API contracts (timezone parameter, current_stock field) unchanged.
In scope: App.tsx statisticsView period markup, StatisticsEvidence current-stock panel, copy keys used only there, CSS, e2e/statistics and shell tests, requirements, docs.
Out of scope: server analytics/timezone handling and current_stock in API/CSV; full suite (STATED: at the end).
Constraints: keep URL-addressable reporting (REQ-UX-b77fdd9e, REQ-UX-4200375b); keep all-project scope note on the global page.
Success signals: e2e shows the compact row and absent elements; DCP shows it.
Evidence: OBSERVED App.tsx:999 metrics-period markup (timezone select, metricsScopeHelp + boundaries, legend); StatisticsEvidence.tsx:43 current-stock panel; tests shell.spec.ts:328 and statistics.spec.ts:51,61,68,81.
Assumptions: UTC stays the default reporting zone (chosen to keep URLs and server buckets unchanged; INFERRED acceptable since cards show "· UTC").
Unknowns: none blocking. Decision-blocking questions: none.
Proposed behaviors: B1 compact row (REQ-UX-aa9f0f6c); B2 timezone via URL only (REQ-FUNC-b3ac688c, REQ-UX-9f1ec9fa); B3 no current-state panel (REQ-UX-7fdffe77, REQ-UX-a24db609).
Path and reason: full - observable UI changes and requirement revisions.

## Design

- D1 App.tsx: metrics-period becomes `<div className="metrics-period-row">` with h2, optional project select, From, Through, Group by, All time button, Export CSV (pushed right); CSS flex row with align-items:flex-end, wrapping on narrow screens; remove the two paragraphs.
- D2 remove the Time zone select; metricTimezone state, route/URL parameter and API queries remain (default UTC).
- D3 StatisticsEvidence: drop the current-stock section; statisticsCopy stock/stockHelp and boundaries/legend keys and i18n reportingTimezone/metricsScopeHelp removed if unused elsewhere.
- Test seams: e2e/statistics.spec.ts (row, absences, URL zone), e2e/shell.spec.ts (zone via URL).
- D4 (round 2 request) StatisticsEvidence becomes only the Summary measure grid (no heading, scope line, explanatory paragraphs, coverage counters or canonical interval); the Messages panel is removed; the Job consumption table is removed because the Jobs tab already shows each job's lifetime and selected-period consumption (list column and detail); the Job duration cards move to the Usage tab without repeated hints. API, Job consumption CSV export and the Jobs integration stay unchanged.
- D5 (round 3 request) Usage: remove the Executor/Model filter inputs, their help paragraph and the Rebuild usage history button (every Statistics read already reconciles journals into usage; `POST /api/v1/usage/rebuild` and the API executor/model parameters stay); the usage table gets sortable column headers reusing `SortHeader` (made generic) with `sortUsageRows` in `src/usageSort.ts` (unknown values last in both directions); the totals line becomes compact label/bold-value chips (`.usage-totals`) that also carry the job elapsed-time values (measured jobs, average, median), replacing the separate Job elapsed time section.

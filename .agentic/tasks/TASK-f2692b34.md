## Frame

Problem: On native Windows, the environment ADORE builds for executor gates,
probes and the conductor's AEGIS strict verification keeps only the names in
`SYSTEM_ENV_KEYS` (OBSERVED: `04_Software/adore/local_execution.py:47-68,140`).
Standard Windows system variables such as `PATHEXT`, `PROCESSOR_ARCHITECTURE`,
`SystemDrive`, `ProgramData` and `ProgramFiles` are dropped (OBSERVED: same lines;
none of them is in the set). Project tooling that relies on them then fails or
misbehaves even though it works in the operator's own shell.
Desired outcome: A native Windows local run gives executor gates, readiness probes
and strict verification the standard Windows machine/system variables of the
ADORE process account, so platform detection and system-folder lookups behave as
in a normal session, while the allowlist stays explicit and forge credential
variables stay excluded.
Actors: the operator running ADORE natively on Windows 11 (STATED: operator review
2026-10-31, `D:/Temp/ADORE_Operator_Review_2026-10-31.md` B5); the coding executor
and the conductor's verification process launched through `local_environment`.
Primary scenario: OBSERVED in the 2026-10-31 operator review on ticket VERA #46
(local OpenCode, Windows 11): strict verification ran `python ../02_Tools/npmw.py
npm run lint|typecheck|check:i18n`; each exited 1 in 0.2 s with "unsupported
platform: win32" because `platform.machine()` returned `''` without
`PROCESSOR_ARCHITECTURE` (OBSERVED: run journal `STRICT_VERIFICATION_FAILED` x2 and
executor question round 3). A Windows component also wrote
`%SystemDrive%/ProgramData/Microsoft/Windows/Caches/*.db` as a literal relative
folder inside the worktree, and `commit_all_if_dirty` (`git add -A`,
OBSERVED: `04_Software/adore/isolation.py:695-715`) committed and pushed it.
Examples: With the fix, a local Windows gate sees `PROCESSOR_ARCHITECTURE=AMD64`
and `PATHEXT` from the ADORE process, `platform.machine()` returns `AMD64`, and
`%SystemDrive%` expands to the real system drive instead of a relative folder.
Counterexamples: A forge credential variable present in the ADORE process (for
example `GITEA_TOKEN`) is still absent from the executor environment. Linux local
execution keeps its current variable set (no Linux-specific defect observed).
In scope: extend the explicit Windows system allowlist used by
`local_environment`; keep `[local].environment` able to set those names as today;
operator/component documentation of the allowlist.
Out of scope: Linux variable changes; isolated executor configuration (review B3);
recovery/drift UX (review B4); container execution (unaffected, separate env
assembly — INFERRED from `SYSTEM_ENV_KEYS` being used only by `local_environment`).
Checkpoint staging changes (STATED: RULING-003).
Constraints: REQ-SEC-f7b9111e requires an explicit environment allowlist that
excludes forge credential variables (STATED: requirement text). The pinned local
policy hashes the effective environment (`environment_sha256`, OBSERVED:
`local_execution.py:236`), and a mismatch is drift that refuses resume, retry and
delete of that run (OBSERVED: review B4, `local_execution.py:338-356`). The
current branch is `task/adore-web-interface`, not the default branch (OBSERVED:
`git branch --show-current`); the user asked to commit on this branch (STATED).
Success signals: offline tests show the added Windows names pass through
`local_environment` and forge credentials still do not; a native Windows probe in
this environment reports a non-empty `platform.machine()`; existing local
execution tests stay green.
Evidence: OBSERVED names present on this host: ALLUSERSPROFILE, COMMONPROGRAMFILES,
COMMONPROGRAMFILES(X86), COMMONPROGRAMW6432, COMPUTERNAME, DRIVERDATA, HOMEDRIVE,
HOMEPATH, NUMBER_OF_PROCESSORS, OS, PATHEXT, PROCESSOR_ARCHITECTURE,
PROCESSOR_IDENTIFIER, PROCESSOR_LEVEL, PROCESSOR_REVISION, PROGRAMDATA,
PROGRAMFILES, PROGRAMFILES(X86), PROGRAMW6432, PUBLIC, SYSTEMDRIVE, USERDOMAIN.
Assumptions: INFERRED — the `%SystemDrive%` folder disappears once `SystemDrive`
and `ProgramData` reach the process (premise: the literal unexpanded name).
Unknowns: which component wrote the cache files (UNKNOWN); whether

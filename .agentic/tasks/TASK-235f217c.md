## Frame

Problem: On a project whose pickup is stopped, Tickets -> Start adds the ready
(and priority) labels on the forge, queues `run --once --ticket N`, the engine
picks nothing, and the operation ends "failed - engine rejected operation" with
no reason (STATED: Gitea #29; OBSERVED below). The Start confirmation panel
appears above the table, away from the clicked row, and names the word
"Priority" instead of the chosen priority label (STATED: #29; OBSERVED).
Desired outcome: an explicit Start either works or is clearly unavailable and
explained when pickup is stopped; any engine refusal keeps a readable, bounded,
redacted reason in the operation result (UI and API); labels are not added when
the start cannot happen (or are withdrawn); the confirmation panel sits by its
row and names the real labels (STATED: #29 acceptance criteria).
Actors: project member or admin using Tickets -> Start (members can Start but
only admins can stop/start pickup - OBSERVED app.py submit 403 admin_required);
the web command worker; the CLI engine.
Primary scenario: an operator imports or enrolls a project (pickup starts
stopped - OBSERVED i18n "Pickup starts paused"; STATED #29 for new projects),
opens Tickets, presses Start on one ticket, confirms the labels.
Examples: OBSERVED in the 2026-10-31 operator review (finding B2, VERA
project): Start on a ticket of a new project with pickup stopped -> the labels
were added and the operation failed "engine rejected operation". INFERRED from
cli.py:648-651: the CLI had printed a JSON summary with `"paused": true` that
the worker discarded.
Counterexamples: pickup active, a free execution slot and an eligible ticket ->
Start already works and must keep working unchanged.
In scope: the Start path (web/app.py start_ticket, web/tickets.py ticket view,
selection blocker codes if needed), the web command worker result
(web/commands.py), the CLI single-ticket exit/reason output (cli.py _cmd_run),
the Tickets UI start panel and copy (TicketWorkspace.tsx, ticketCopy.ts, 4
locales), help (Tickets topic, 4 locales), docs, CHANGELOG/release note, tests.
Out of scope: changing who may stop/start pickup; the polling loop's own
selection rules; other operations' result wording beyond the shared worker
result format (#29 names Start); withdrawing labels on a late refusal
(RULING-003); the jobs UI items of #35 JOBUI (STATED separate ticket). The Stop
panel placement is in scope (RULING-004).

## Design

**Approach.** Refuse early, explain late. start_ticket checks
`state.is_paused()` right after the idempotency replay and before any forge
read or label write (REQ-FUNC-4e5e56ed); ticket_view applies the same state to
the Start fields (REQ-FUNC-ef5a60d0). For refusals that can only happen in the
worker (slots busy, AEGIS probe, ticket changed, pickup stopped after the
start was queued, external conductor holding the lock), the CLI prints one
stable line `error: ticket #N not started: <code>` (REQ-FUNC-6c87ec5b); the
worker captures the command's combined output, keeps a bounded redacted tail
as `detail` (REQ-FUNC-fbb6448c) and parses the line for the operation's own
ticket into `reason` (REQ-FUNC-6055f2c6). The UI localizes the reason and shows
the detail (REQ-UX-5fb31254). Rejected: deriving reason from the CLI's JSON
summary (not a contract, and absent for lock-held); encoding reason/detail in
`result` (cut to 1000 characters, free text shown raw by every client).
**Interfaces and data.** Web schema 15: `operations.reason TEXT NOT NULL
DEFAULT ''` and `operations.detail TEXT NOT NULL DEFAULT ''` (fresh schema and
a v14->15 ALTER step); `WebStore.finish(id, status, result, *, reason="",
detail="")`; GET /api/v1/operations/{id} adds `reason` and `detail`. Worker:
`CommandOutcome(code, output)`; `_run` uses `stdout=PIPE, stderr=STDOUT` so the
lines keep their order and returns it (timeout keeps partial output with 124);
a runner may still return a bare int (no output) - every existing fake does.
Reason codes: pickup_paused, at_capacity, aegis_probe_failed, not_eligible,
conductor_busy; result strings stay as today. Ticket view: blocked_by
`pickup_paused` with can_start/adds_ready_label/needs_priority false, only for
tickets whose own Start blocker is None. API 409 keeps the existing shape
`{"code": "ticket_not_startable", "message": "pickup_paused"}`.
Shared helpers (constraint: one ANSI/tail implementation): adore/util.py gains
`ANSI_ESCAPE` and `output_tail(text, redact, lines=20, chars=2000)`;
orchestrator._stderr_tail calls it with `_sanitize(t, None)` (behavior
unchanged, #28 tests guard it); the worker calls it with a public
`redact_text` extracted from web/jobs.py (`_text` keeps using it), whose
patterns also cover Bearer/Basic and quoted values.
UI: Operation type gains optional reason/detail; new web/src/operationReason.ts
maps reason -> sentence (4 locales); Tickets, Jobs and App status show the
sentence (else result) and a `<pre>` detail block; Tickets keeps labels_added
in its notice to name kept labels on failure (REQ-UX-21f0f5a5); Start/Stop
confirmations render as `<tr><td colSpan>` right after the clicked row
(REQ-UX-61a21b3d); the start message joins the ready label and the `priority`
state (REQ-UX-c18f6fec); REASONS gains pickup_paused and a 409 whose detail is
pickup_paused shows that explanation (REQ-UX-3cafa0cc).
**Files and test seams.** adore/web/app.py, web/tickets.py, web/commands.py,
web/store.py, web/jobs.py, util.py, orchestrator.py (call site), cli.py;
web/src TicketWorkspace.tsx, ticketCopy.ts, operationReason.ts (new),
JobWorkspace.tsx, App.tsx, styles; help tickets/jobs topics (4 locales).
Tests: tests/test_web_tickets.py (4e5e56ed, ef5a60d0), tests/test_profile_cli.py
or a new CLI test beside the existing run --ticket tests (6c87ec5b),
tests/test_web_commands.py and a store migration test (fbb6448c, 6055f2c6),
tests/test_orchestrator.py unchanged as the #28 guard, web/tests node tests for
operationReason.ts and helpers, web/e2e/tickets.spec.ts for the UX rows (run as
that single spec only).
**Risks and open decisions.** Schema 15: an older ADORE build refuses the

say it in CHANGELOG. The captured output is held in memory as today
(capture_output=True already). Redaction is best effort (patterns), as for
jobs projection. A race (pickup stopped after the start was queued) still adds
labels, then reports pickup_paused with the kept labels (RULING-003).

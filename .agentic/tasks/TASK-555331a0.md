## Design

### Approach

- STATED (ticket #68): extraction only; composition remains Python-owned. D1 (REQ-FUNC-1f56bfac): add `adore/prompts.py` and 25 Markdown resources, not a package `prompts/__init__.py` (technical constraint: the sibling directory must not shadow the loader module).
- INFERRED (inspected `_stage_prompt`): use `stage/{intro,ticket,active-task,instructions,journal,autopilot,completion,single-stage,frame,quick-label,recovery-context,human-thread,packages-enabled,packages-disabled,network,closing}.md`. These are the eight initial paragraphs, two frame branches, two wrappers, two permission variants, network suffix and closing paragraph.
- INFERRED (five inspected failure_context sites): `recovery/{revalidation-route,integration-conflict,continuation,no-progress,strict-verification}.md`; `review/{pipeline,ticket-content-changed}.md`; `system/{internet-off,server-internet}.md` complete D1's inventory. Raw executor/AEGIS errors remain data, not new templates.
- D2 (REQ-FUNC-e8d63a5c): `Orchestrator.from_config` constructs one catalog and injects that same object into the conductor and `build_executor`/`PiExecutor`; direct conductor construction defaults to eager catalog creation. Standalone launchers default to their own catalog at construction. No import-time reads, process-global cache, configurable path or reload mechanism. Tests/direct callers can inject one shared catalog as production does.
- D6 (REQ-FUNC-14872c0d): replace literal fragments with render calls at their existing sites; retain all conditions, ordering, `description.strip()`, `_sanitize`, `author: body` rendering, space concatenations, `\n\n` joins and native/internet selection. Reject a monolithic stage template: it would move conditional composition out of code.

### Interfaces and data

- D1/D3 (REQ-FUNC-1f56bfac, REQ-FUNC-5bd765bb, REQ-SEC-66431463): `PromptCatalog()` reads a fixed required relative-path inventory rooted at `Path(__file__).with_name("prompts")`; `render(fragment: str, **values: str) -> str` accepts only catalog keys. Stored templates are private, read-only after successful construction; caller data is substituted exactly once with `Template.substitute`, never `safe_substitute` or recursive parsing. No runtime dependency or persisted format is added.
- D3: ticket uses `$iid`, `$title`, `$description`; active-task uses `$task_id`, `$stage`, `$path`; completion/closing use `$aegis`, `$task_id` (closing also `$questions_file`); quick-label uses `$quick_label`; wrappers use `$context`/`$thread`; network uses `$mode`; recovery route uses `$task_id`, continuation uses `$task_id`/`$evidence`, strict verification uses `$task_id`/`$evidence`. Other fragments have no values. Convert numeric IID at the caller; keep sanitization and command-value ownership where they are now.
- D4 (REQ-FUNC-8256ca8e, REQ-REL-3eb9bb9e): resource bytes are strict UTF-8, LF, exact project `<!-- ... -->` header followed by one delimiter LF, then body. Remove exactly that canonical prefix and delimiter, not body whitespace. Do not append a final LF to a body unless the old literal had one; no `.strip()`, dedent or universal-newline conversion. Non-leading comments remain body data. Missing/malformed legal prefix is refused as malformed resource rather than leaked to Pi.
- D5 (REQ-REL-6fc1aa99, REQ-REL-d0663c1d, REQ-REL-3eb9bb9e, REQ-REL-ab48c99a, REQ-REL-87abf8e4): `PromptError(RuntimeError)` includes the relative fragment filename and reason. Read with `read_bytes().decode("utf-8")`, wrap OSError/UnicodeDecodeError, validate `Template.is_valid()` before publishing the complete catalog, and wrap missing-value KeyError at render. Unknown fragment keys also fail with a named PromptError; no fallback, partial catalog, automatic repair or swallowed error. Fresh construction is the retry boundary after fixing shipped files.
- D2/D6: add optional catalog injection to conductor, `build_executor` and `PiExecutor` constructors only; do not change the executor-neutral `Executor.run_gate` contract, Pi RPC transport or `pi_rpc_argv` notice parameter. Remove the offline literal constant; launcher renders from its catalog at the existing native/internet branch. Both ticket-change note usages (journal metadata and thread suffix) render the same loaded review fragment, preserving their text.

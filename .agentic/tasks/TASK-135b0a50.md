## Frame

Problem: the global Jobs page still has the old layout - a Job scope panel with worker status and two explanatory sentences, a Ticket number start form the project hub already dropped as redundant, then search and the job table - while the project hub Jobs tab offers Tickets/Jobs sub-tabs (STATED: "acum, panourile de jobs nu sunt updatate asa cum sunt in projects. Poti sa le faci ca in projects?"; choice: "Selector + aceleasi sub-tab-uri").
Desired outcome: /jobs = compact project selector row; selected project -> Tickets (default) / Jobs sub-tabs exactly like the hub; All projects -> job list only; no ticket-number form or scope/worker explanations; worker status only on problems.
Actors: administrators and developers.
Primary scenario: open Jobs -> All projects list; pick a project -> Tickets with Read tickets; switch to Jobs -> filters + table; a run link opens the Jobs sub-tab with details.
Examples: nilo screenshot (Job scope + Worker available + help, Ticket number form, Search jobs).
Counterexamples: hub Jobs tab unchanged; job links, run deep links and search/paging unchanged; manual start remains available through Tickets Start; retry/cancel from job detail unchanged.
In scope: App global Jobs markup and route/state for the sub-tab, JobWorkspace scope panel/start form removal, routes view=jobs, copy cleanup, e2e fixture tickets #43/#44, e2e/unit tests, requirements, docs.
Out of scope: backend APIs; full suite (STATED: at the end).
Constraints: REQ-UX-a7969a9d (queue vs asynchronous outcome) keeps coverage through Tickets Start; REQ-UX-3dda4965 keeps applying to the remaining repository server placeholder.
Success signals: e2e shows the new layout and start flows via Tickets; DCP shows it.
Evidence: OBSERVED JobWorkspace scope panel (lines ~251-255) and start form (~256-259); App page === "jobs" renders JobWorkspace mode jobs; hub uses TicketWorkspace + JobWorkspace startForm={false}; e2e start tests jobs.spec:140,313, dashboard.spec:158, shell.spec:270.
Assumptions: Tickets is the default sub-tab on /jobs as in the hub; the chosen sub-tab survives project changes (INFERRED for consistency).
Unknowns: none blocking. Decision-blocking questions: answered (selector + same sub-tabs).
Proposed behaviors: B1 compact selector, All projects list; B2 project sub-tabs Tickets/Jobs with view=jobs URL; B3 no start form/explanations, worker problems only (REQ-UX-29d41b39); B4 manual start through Tickets (REQ-UX-a7969a9d tests); B5 REQ-UX-3dda4965 kept on the repository server placeholder.

## Design

- D1 App renders the global Jobs page: `section.panel.compact` with `#jobs-project` selector (All projects + projects) and, when a project is selected, the hub's `.jobs-subtabs` tablist reused (Tickets -> TicketWorkspace, Jobs -> JobWorkspace); All projects -> JobWorkspace only.
- D2 routes: `/jobs` gains `view=jobs` (jobsView) like the hub; App currentRoute/applyRoute keep jobsView for the jobs page (run -> jobs).
- D3 JobWorkspace no longer renders the scope panel or the ticket-number start form (prop `startForm` removed); worker status only as an alert when unavailable/failing; command() keeps retry/cancel; unused copy removed.
- D4 e2e fixture adds open tickets #43 (engine exit 7) and #44 (engine exit 0); start tests use Tickets Start.
- D6 (RULING-001) TicketWorkspace takes `projects` (+ `showProject`): one Promise.allSettled read per project, rows keyed by project and ticket with their own label policy, a Project column and per-project read errors when several projects are shown; App renders the sub-tabs for All projects too (archived projects excluded from ticket reads); `view=jobs` works without a project; Tickets stays the default.
- D5 REQ-UX-3dda4965 stays: the Connect repository server placeholder carries the localized example marker (verification moved there).
- Test seams: jobs.spec new layout test and rewritten start tests, dashboard.spec developer start, shell.spec developer layout, tickets.spec row count, routes.test view=jobs.

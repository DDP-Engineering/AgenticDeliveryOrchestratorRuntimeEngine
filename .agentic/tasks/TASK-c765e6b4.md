## Frame

Problem: ADORE is CLI-first and its metrics page is a static export; users need an installed web interface.
Desired outcome: Authorized administrators and developers configure, operate, and inspect ADORE with localized responsive views and honest usage metrics.
Actors: Platform administrator, developer assigned to projects, ADORE conductor, forge reviewer.
Primary scenario: Administrator installs offline, signs in as admin/admin and configures a project; developer signs in, sees assigned project and starts/retries/cancels work; administrator sees financial metrics; human reviews and merges draft MR.
Examples: A developer starts an eligible ticket in an assigned profile. Administrator sees daily token/cost coverage across projects.
Counterexamples: Developer reads another project's job or any cost; corrupt account DB recreates admin/admin; web call bypasses conductor lock.
In scope: Plan sections 4-11, including optional FastAPI, React, offline media, login/RBAC, controls, analytics, locales and theme.
Out of scope: Merge automation, SSO, multi-host execution, browser-held forge/model secrets.
Constraints: Preserve AEGIS and draft-only human merge contracts, CLI compatibility, offline unit tests, repository docs, bounded autonomous work.
Success signals: Runnable bundle; API denies forbidden access; complete pages and locales; controls obey engine; known/unknown metrics; network-blocked install.

Assumptions: One internal execution host until scale is agreed.
Unknowns: Initial load, local model server/protocol, retention and reporting timezone.
Decision-blocking questions: None for the confirmed Windows/Ubuntu, retained approval and administrator pricing scope.
Proposed behaviors: Seven draft requirements linked above; preserve existing engine contracts.
Path and reason: Full. New UI/API/data/dependencies/security contracts require specify and design.

## Design

- Requirements: Seven active IDs map to the current web auth/store, API, worker, analytics, frontend and packaging seams. Ten draft IDs now capture the approved plan's remaining identity, endpoint, analytics, accessibility and deployment behavior.
- Components: Optional FastAPI adapter uses existing ProfileStore/StateStore/config/metrics. React bundle calls same-origin versioned API. Durable web database owns accounts, memberships, sessions and commands; ADORE journals remain run truth.
- Interfaces: Explicit project IDs; role and membership checks on every query/action; backend strips financial fields for developers. JSON error codes distinguish invalid, forbidden, conflict, and corrupt state.
- State/concurrency: SQLite transactions protect web identity and queue. A worker executes bounded commands through existing conductor/CLI lock semantics; retries require idempotency and reconciliation.
- Compatibility: Preserve current candidate approval and human merge. Web dependencies optional; CLI baseline remains stdlib-only. Existing profiles imported without changing their state.
- Security: Initial admin/admin is hashed and initialized only for a truly empty store; force change at first login is recommended in planning but not yet approved. Cookies and CSRF guard mutations.
- Risks: Selected-ticket start requires an explicit engine seam; raw logs can include costs and secrets; mixed CLI/web config edits need version checks; offline media must include exact prerequisites. Document unsupported subfeatures instead of claiming them complete.
- Open decisions: Deployment exposure and reporting timezone. First release targets up to 10 users/20 projects; OpenAI-compatible HTTP is the first local endpoint; history stays indefinitely with manual backup.

### Expanded contracts

- REQ-FUNC-c369cfa6 owns immutable project IDs in profiles, grants, commands and prices; name reuse cannot adopt an old grant.
- REQ-FUNC-fec24fc3 and REQ-FUNC-2710d0f4 use a validated OpenCode-compatible endpoint and a bounded disposable container probe with no image pull. A host-only connection is not readiness.
- REQ-DATA-2a1292db and REQ-FUNC-7bb356df keep launch observations in the run journal, deduplicate numeric events by launch identity, and reconcile into SQLite without changing run state. Nullable cache categories are subsets of input tokens.
- REQ-FUNC-b3ac688c and REQ-FUNC-930e3ae0 use UTC evidence, selected IANA reporting timezones, separate reported/estimated money and explicit cohorts.
- REQ-PLAT-487933ca and REQ-PLAT-3ef15c3a use checksummed host media, local wheels, image prerequisites and a loopback API behind a TLS proxy.
- REQ-UX-1a34d639 keeps the four locales, themes and tabular chart alternatives usable at compact through wide layouts.

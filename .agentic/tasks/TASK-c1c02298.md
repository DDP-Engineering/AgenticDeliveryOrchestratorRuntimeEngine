Problem:
- STATED (ticket #49): Read tickets / Show details exposes literal Markdown in long ticket descriptions and comments, making them hard to read; VERA #84 (PLG-22 git plugin) is the supplied motivating example.
- OBSERVED: `04_Software/web/src/TicketWorkspace.tsx` renders description and comment bodies inside `p.ticket-text` as React text; `web/e2e/tickets.spec.ts` currently expects literal `**bold**` in comments.

Desired outcome:
- STATED (ticket #49): descriptions and comments open as rendered rich text by default, with a Rendered / Markdown source switch beside Description that applies to comments too and remembers the user's choice. Source view shows the exact Markdown received, not reconstructed output.

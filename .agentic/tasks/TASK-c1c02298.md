## Design

### Approach

- INFERRED D1 (REQ-UX-95f72cce, REQ-SEC-29fc8db7): add `web/src/forgeMarkdown.ts`, a React-only `ForgeMarkdown` renderer using pinned `react-markdown` 10.1.0 and `remark-gfm` 4.0.1. Use `createElement` in this `.ts` module so native Node TypeScript unit tests can render it with `react-dom/server`, without a JSX test loader. Keep the help parser unchanged. Reject a handwritten nested-GFM parser (maintenance/security complexity) and an HTML-string parser/sanitizer pipeline (ticket forbids HTML injection APIs).
- INFERRED D2 (REQ-UX-a393abfe, REQ-UX-a371d306): App owns one current mode and passes it to both TicketWorkspace mounts; each expanded detail has the same controlled native select beside Description. Both description and comments use ForgeMarkdown in rendered mode, or `pre` with the untouched API string as a React child in source mode. Apply the existing fallback only to an empty description before either presentation; do not trim, normalize or round-trip source through the parser.

### Interfaces and data

- OBSERVED: `store.py` schema 15 has nullable language/theme and transactional partial updates; `app.py:PreferenceInput` accepts omitted/null fields; preference routes are account/CSRF protected. `App.tsx:updatePreference` is optimistic with error rollback; both TicketWorkspace call sites currently receive no mode.
- INFERRED D3 (REQ-DATA-8532e8f2, REQ-DATA-529c5e6e; existing account/CSRF contract): add `ticket_body_mode` to GET/PATCH `/api/v1/me/preferences`, values `rendered` or `source`. GET null means no saved selection and UI Rendered. PATCH omission leaves it unchanged; explicit null or any non-enum value fails request validation with 422 `invalid_request` before writes (field validator must distinguish omitted from explicitly supplied null). Do not change language/theme null semantics. Store validates the same enum and preserves other fields in the existing transaction; no user ID is accepted from the browser.
- INFERRED D4 (REQ-DATA-a493390d; root stored-data rule): add nullable TEXT `user_preferences.ticket_body_mode`, update schema/column checks and queries, and bump the single supported web schema to 16. No ALTER, migration, compatibility reader or automatic deletion. Old databases use existing refusal naming `web.db` and `web.db.initialized` to delete. Invalid saved mode raises WebStoreError; routes return existing 503 `preferences_corrupt`, without repair, including on partial writes that encounter corrupt stored preferences.
- INFERRED D5 (REQ-REL-5bb00e92, REQ-DATA-8532e8f2): App applies saved mode on authenticated initialization/sign-in, resets it to Rendered on session clear, and guards reads/writes with captured account/session generation. Validate preference responses before applying modes; malformed responses surface `unexpected_response`, never become a mode. Save optimistically with one in-flight ticket-mode PATCH per account (synchronous ref guard); all mode controls stay mounted/focusable with `aria-disabled` while pending and ignore further selections until completion. Success confirms only that field, not stale language/theme snapshots; failure restores the last confirmed mode and displays existing localized error feedback. No automatic retry; the same choice can then be explicitly attempted again. Ignore old-account responses; navigation retains App state. Browser cross-device persistence means read on sign-in/reload, not live synchronization between active tabs.
- INFERRED D6 (REQ-SEC-29fc8db7, REQ-SEC-777ae52c, REQ-SEC-fc07c123, REQ-SEC-a0ea8c6d, REQ-SEC-f29221e6): configure only remark-gfm, no rehype-raw, HTML hydration, raw DOM insertion or syntax highlighter. Keep raw HTML as visible literal React text (do not use skipHtml, which drops it). Custom anchor mapping plus URL transform admit only explicitly absolute `http://`, `https://` or `mailto:` destinations validated with URL, rejecting controls, whitespace/encoded-scheme tricks and missing web hosts; invalid links render children without an anchor. Safe anchors set only controlled href/title plus `_blank` and `noopener noreferrer`, never spread token props. Custom image mapping always emits a localized inert placeholder with alt text or generic image label; never img, src, CSS URL or fetch. Read-only task inputs are disabled checkboxes. Unsupported nodes retain readable raw/text content; malformed Markdown is parser-managed inert content. Metadata stays on its current text/safeEvidenceLink path.
- INFERRED D7 (REQ-UX-f79c7d6e, REQ-UX-a560ba57, REQ-UX-58401aa1): controlled selects use unique detail-scoped labels/ids, localized mode/choice/pending/image text from ticketCopy, stable row keys and existing focus outline. Prose wraps anywhere; `pre` and table wrappers scroll locally with focusable overflow regions; constrain detail/table cell min/max widths so neither rendered nor source content widens the outer page. Scoped rich-text CSS uses existing theme tokens, not global help styles.

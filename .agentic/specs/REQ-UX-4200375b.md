# REQ-UX-4200375b — Address every web view by a stable URL

## Behavior

- A change of view path made by the user (sidebar, links, tabs, row actions)
  writes a new browser history entry. Changing only the selected project or
  job within the same view updates the current entry's query instead, so
  Back returns to the previous view rather than the previous selection.
  Back and Forward re-render the view named by the URL.
- Loading or reloading any listed path renders that view once the session is
  known. Signed-out users see the sign-in card; after sign-in they land on the
  originally requested path. Sign-out returns to `/`.
- Normalization replaces (does not add) the history entry: unknown paths go to
  `/`; administrator paths opened by a developer go to `/`; a project ID that
  is not in the user's authorized project list goes to `/projects` with the
  localized `project_not_found` error.
- Filters, sort order, page numbers and form drafts are not part of the URL.
- The required-password-change card does not change the URL.

## Data / interface

| Path | View | Notes |
|---|---|---|
| `/` | Overview | optional `?project=<id>` selects the project |
| `/projects` | Projects list | |
| `/projects/new` | Add project | administrators |
| `/projects/import` | Import project | administrators |
| `/projects/<id>` | Project details, Overview tab | `<id>` is the immutable project ID |
| `/projects/<id>/configuration` | Project details, Configuration tab | |
| `/projects/<id>/jobs` | Project details, Jobs tab, Tickets sub-tab | `?view=jobs` selects the Jobs sub-tab; `?run=<run_id>` opens that job's detail in the Jobs sub-tab |
| `/projects/<id>/statistics` | Project details, Statistics tab | optional `?tab=summary|usage|quality|trends` and reporting `from`, `through`, `timezone`, `granularity` |
| `/projects/<id>/prices` | Project details, Settings tab | legacy link; replaced by `/projects/<id>/configuration` for every role |
| `/jobs` | Jobs | optional `?project=<id>&run=<run_id>` |
| `/metrics` | Metrics | optional `?project=<id>` (absent = All projects for administrators) and `&tab=summary|usage|quality|trends|projects` |
| `/admin/status` | System status | administrators |
| `/admin/users` | Users | administrators |
| `/admin/audit` | Audit | administrators |
| `/account` | My account | every signed-in user |

Paths are case-sensitive, a trailing slash is ignored, and unknown query
parameters are ignored. Route parsing and formatting live in a pure module
(`web/src/routes.ts`) so they are unit-testable.

## Examples

- `/projects/88efed3d79945faab27a52d1a11f219b/configuration` -> project
  details, Configuration tab.
- `/jobs?project=88ef...&run=run-26` -> Jobs for that project with job
  `run-26` details open; an unknown run shows the Jobs list without details.
- `/admin/users` as developer -> replaced by `/`.
- `/nope` -> replaced by `/`.
- Browser Back from `/projects/<id>` after arriving from `/projects` -> Projects.

## Acceptance

- Route unit tests cover every table row in both directions plus the
  normalization cases above.
- Browser checks cover reload, Back/Forward and signed-out deep links.

## Assumptions and open decisions

- Path URLs are served by the existing SPA fallback; no server route changes
  are required (task RULING-002).

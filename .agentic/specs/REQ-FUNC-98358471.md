# Recorded session page contract

STATED: #92 requests completed physical launch history and byte line-start cursors.
OBSERVED: current launch archives are `io/archive/<stage>-attempt-N-attempt1[-K]`;
collision K is any decimal integer at least two. Metadata records archive completion,
exit code and timeout; no start timestamp exists.

## Public reader and routes

`list_sessions(run)` returns metadata newest first. `read_session(run, attempt_id,
cursor=0, limit=200, include_cost=False)` reads the authorized run directory only.
The existing authenticated job lookup and project-grant checks wrap both GET routes:

- `/api/v1/jobs/{project_id}/{run_id}/sessions`: `{sessions: Metadata[]}`.
- `/api/v1/jobs/{project_id}/{run_id}/sessions/{attempt_id}?cursor=0&limit=200`:
  `{session: Metadata, items: Item[], next_cursor: number|null}`.

Metadata has exact archive `id`, `stage`, positive `attempt`, `start_at: null`, UTC
`end_at` from archive creation, `outcome: succeeded|failed|timed_out`, and `exit_code`.
No state or file format is written or changed. Exact safe archive identity and
regular-file/parent identity guards precede reads. Missing or unknown attempts use
404; unsafe/corrupt evidence uses the existing typed evidence error. HTTP validates
cursor safe integers and limit 1..200. Successful responses use `Cache-Control: no-store`.

## Source items

One source line contributes at most one outer item; `limit` strictly caps outer items.
An assistant `message_end` can contain text, readable thinking and usage simultaneously.
Such an outer item is `{kind: assistant, text: "", parts: Item[]}` with two or three
non-nested typed assistant/reasoning/usage parts. The UI flattens those parts into
readable blocks. This preserves every accepted part while keeping the cursor a byte
offset at the next complete source-line start, even with limit one.

Ordinary items have `kind` and `text`. Tool items additionally have `tool` and
`call_id`; results carry boolean `is_error`. Usage has recognized token counters and
administrator-only structured costs. Literal user/agent/tool text stays unredacted.
System messages, streaming deltas, toolResult message duplicates and agent_end message
lists produce no item. Readable reasoning is collapsed in the UI.

Each text field is at most 16 KiB UTF-8 including its visible truncation marker.
Malformed JSON, duplicate keys, bad recognized shapes, nonfinite/invalid usage,
oversize records and executor omission/truncation markers become notices. A line is
bounded at 256 KiB; skipping a larger physical line is bounded by the 64 MiB source
ceiling. Larger files yield a size-bound notice without scanning. Normal pages scan
at most 4 MiB between records. Only LF-complete lines are projected; an interrupted
tail of a completed archive ends pagination. Empty pages can result from ignored
records. `next_cursor: null` means no remaining complete archived records.

## Verification and limits

Offline API tests replay spike stdout and inject system/duplicate keys, exact fake
secrets, malformed/oversize/truncated lines, invalid cursor and identity, corrupt
metadata, huge numeric usage, collision suffix ten and linked files. Model tests
validate bounded parts and role costs; browser tests read real archived fixtures
and exercise attempt selection, collapsed reasoning, tools and Load more.
Live sources extend this same grouped-item reader through the protocol in
`REQ-FUNC-20e2ffe7.md`; instruction delivery is not implemented.
